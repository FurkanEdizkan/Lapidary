# S3 — Peer sharing out

**Status:** open
**Branch:** `chore/remove-sharing`
**Wave:** 6 · **Kind:** Rust + web · **Depends on:** S1 (the peer arm of `main.rs`) · **Migrations:** 0056

## Why

The owner decided on 2026-10-16 that sharing between installations goes. It is the `lapidary-peer` crate (3,614
lines), about 3k lines in `lapidary-db` (`shares`, `sharing`, `mirror`, `pulls`), about 1.1k in `lapidary-api`
(`shares`, `sharing`), ten migrations, `deploy/compose.sharing.yaml` and the sharing screens. Since the pivot,
shared libraries show no pictures at all.

## Facts to check before building

- Every table created by 0037–0043, 0052 and anything else the sharing modules read or write; foreign keys from
  core tables (`part`, `library`, `revision`) into them, and columns on core tables that only sharing reads
  (e.g. a mirrored-from or asks-first flag).
- `bin/lapidary-server/src/main.rs`'s `Role::Peer` arm and its config fields (`peer_dir`, identity key).
- Web: `routes/sharing*.tsx`, `components/ShareDialog.tsx`, the `sharing` strings block, nav entries, and any
  part-page or folder-page line that mentions shares.
- `scripts/e2e/sharing-shots.mjs` and `group.sh`, and the flows in `flows.mjs` that drive sharing.

## Rules

- 0056 drops tables and columns in dependency order and nothing else. Old migrations are not edited.
- No core behaviour changes: browse, search, pictures, upload and download are untouched.
- CLAUDE.md loses the `peer` rule (the lead commits it with the merge).

## Stages

1. Rust and migration. **Tests:** `verify slice` green; `migrations.rs` asserts the tables are gone.
2. Web and the rig. **Tests:** `npm --prefix web test` green; `flows.mjs` passes with the sharing flows deleted.

## Done when

Nothing names peer, share, mirror or pull outside the ledger, and the Record has the lines removed.
