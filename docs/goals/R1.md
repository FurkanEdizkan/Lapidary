# R1 — The card shows a picture; the viewer loads the original

**Status:** ready at bb8db66, gate log target/verify-R1.log
**Branch:** `feat/picture-first`
**Wave:** 4 · **Kind:** web (+ one db read) · **Depends on:** — · **Migrations:** —

## Why

The owner's call (2026-10-03): Lapidary is a **visual library you look through and search**, not a renderer.
Rendering a preview of every model is complexity bought for a picture we can simply store. So the card's
picture becomes the part's own image, and the 3D view becomes something a person asks for by pressing
**view** — at which point the browser loads the original mesh itself.

**This goal must land before production stops (R3).** Two reasons, both measured rather than guessed:

- The grid reads its picture from the `thumbnail` derivative (`repo.rs:2061`), **not** from `part_image`.
  Purge the renders first and every card goes blank.
- `Viewer.tsx`'s rung effect returns early when `tessellationL0 === null`. So a part with no rung is
  **silently un-viewable** — no error, no spinner, nothing to diagnose. The viewer has to stop needing rungs
  before rungs stop arriving.

## Facts checked (2026-10-03, `73c4836`)

- `FEATURES.md:334` says a user image cannot beat a render without "a 17th column". **Stale.** `GridRow`
  became a named `#[derive(sqlx::FromRow)]` struct with seventeen columns when `removed_us` landed, and its
  own doc says "a card that ever needs it costs a field". Correct the line.
- The real constraint is smaller: the grid carries only **inline** bytes, so an image over `INLINE_LIMIT`
  (64 KB, `images.rs`) needs the card to emit `/api/blob/{hash}`. `blob.rs` already serves images with
  `IMMUTABLE` caching and checks `image_is_reachable` first — content addressing is not authorization.
- `part_image` carries `fit`, `focus_x`, `focus_y` (`0019_image_framing.sql`). Only `Framed` in
  `PartDetail.tsx` honours them; `Card.tsx` hardcodes `object-contain`.
- `glb.rs` performs **no axis swap**, so today's viewer already shows Z-up STL geometry; `STLLoader` on the
  same bytes reproduces that exactly. **3MF is the risk**: `parse_3mf` applies unit scale and build
  transforms in Rust, and three's `3MFLoader` applies its own.
- The part tree the viewer draws came from the GLB's `extras.parts`, which `glb.rs` wrote. No stock loader
  provides it, so explode and hide go with it.

## Rules

- **No new request per card.** Whatever the card shows arrives with the page, as the thumbnail does today.
- The viewer is **lazy and asked for**. Nothing loads a mesh because a page opened or a pointer moved.
- Dark only, motion 120/180/280 ms, transform and opacity, reduced motion respected. Strings through
  `strings.ts`.

## Stages

1. **The card's picture** — one LATERAL for the part's first `part_image` in the same page query, inline
   bytes riding as they do now and a `/api/blob/{hash}` URL when they do not. `Card.tsx` honours `fit` and
   `focus`. A part with no picture gets an empty state that names its format rather than apologising.
   **Tests:** a card with an inline image, a card with a blob-backed one, a card with neither; the page
   makes exactly one request; `fit`/`focus` reach the element's style.
2. **The viewer loads the original** — `STLLoader`/`OBJLoader`/`3MFLoader` by format against
   `GET /api/revisions/{id}/download?variant=original`. Out: the L0/L1/L2 ladder, `requestRung`, the `fine`
   gate, PMI annotation, `placeEntities`, explode, hide, the ghost overlay. A STEP part shows no **view**
   button and keeps its download.
   **Tests:** the loader chosen per format; and **one fixture per format whose client-side bounding box
   equals `PartDetail.bboxMm` within tolerance** — one assertion that catches axis, unit and 3MF-transform
   drift together.
3. **The engine half goes** — delete `turntable.ts` (a hover spin over 50 cards would fetch 50 original
   meshes), `Measure.tsx`, `lib/measure.ts`, `lib/annotations.ts`, `Likeness.tsx`, `lib/likeness.ts`,
   `routes/duplicates.tsx` and their tests; the review line in `index.tsx`, "folded into" on `removed.tsx`,
   the dashboard's duplicates widget, the `likeness` strings block.
   **Tests:** `Grid.test.tsx` asserts **no `<canvas>` on hover at any setting**; a saved dashboard layout
   holding the now-unknown duplicates widget **drops it rather than throwing**.

## Done when

The web suite and build are green, a card shows its own picture or an honest placeholder, pressing view
paints from `?variant=original`, and nothing fetches a mesh unasked. `verify slice` green.

## Record

**Built.** Lapidary's card is a picture and its 3D view is asked for.

- **The card's picture** — `grid_columns!`/`grid_laterals!` gained one LATERAL for the part's
  first `part_image` (`ORDER BY position, id LIMIT 1`, riding
  `part_image_part_id_position_idx`) and nine columns: `file.format` and the picture's id,
  inline bytes, hash, origin, source URL, position and framing. `GridRow` is 26 fields now;
  `PartRow` carries `source_format` and `image: Option<PartImageRow>`; `PartCard` carries
  `sourceFormat` and `image: PartImage | null`. `images::part_image` is the one place a stored
  row becomes a `src`, shared by the gallery and the card, so "inline rides as a `data:` URL,
  a blob is addressed at `/api/blob/{hash}`" is decided once. `Card.tsx` shows the picture with
  `0019`'s `fit`/`focus` applied through `pictureStyle`, the render behind it as a fallback, and
  an empty state that names the format. No request per card: the grid's own code asks for
  nothing, and a blob-backed picture is one immutable `<img>` load.

  CSS2D renderer. `Preview` offers **view** only for the three mesh formats and only with WebGL;

- **The engine half of the frontend** — deleted `turntable.ts`, `Measure.tsx`, `lib/measure.ts`,
  `lib/annotations.ts`, `Likeness.tsx`, `lib/likeness.ts`, `routes/duplicates.tsx`,
  `lib/prefetch.ts`, `warm.test.ts`, `Viewer.test.ts` and their tests; the hover warm and

606.6 kB (gzip 153.9 kB) and `grep -l WebGLRenderer web/dist/assets/*.js` matches that chunk and

**The guard against orientation drift.** `fixtures/bbox-mm.json` states each mesh fixture's
extent in millimetres, and two tests assert against it: `lapidary-cad/src/measure.rs` for the

three's `ThreeMFLoader` reads `<model unit>` and then ignores it, so a centimetre file loaded ten

(all six 3MF units, via the `fflate` the loader itself imports). The committed 3MF fixture is in
millimetres, so the stated test would have passed on that bug — `mesh.test.ts` builds a plate in
four units inline to catch it.

**A test that would have passed on broken code.** The card's "picture first, render as a
fallback" rule: every card in the first version of the grid test had `thumbnail: null`, so
`image ?? thumbnail` and `thumbnail ?? image` were indistinguishable. A card carrying both —
which is every part today — is what catches it.

**Decided without the owner.**
- **The thumbnail stays as the card's fallback** until R4 purges the renders. Every part has a
  render and none has a photograph, so dropping it now would blank the grid this goal exists to
  keep working. After the purge it is the picture or the format.
- **The part page's poster is the gallery's first image**, off the request `Gallery` already
  makes, not the thumbnail alone. Nothing between here and R6 gave the detail page a picture, so
  without this the part page would show an empty frame after R4 while its gallery strip below
  held the picture.
- **The first-run bench is gone.** It was three bundled glTF rungs on a canvas, which loaded the
  whole renderer on the one page with nothing of its own to render, and nothing produces rungs
  any more. The heading, the sentence and Upload were always the page. `web/public/first-run/`
  deleted.
- **No warm-up at all.** `warmViewer`, `prepare()` and `loadViewerWhenIdle` are gone with the
  hover prefetch: `prepare()` created a `WebGLRenderer`, and therefore a canvas, on hover — which
  is no longer defensible when opening a part shows a picture.
- **The PMI list and the assembly tree were kept, their view-coupled controls removed.** Both
  read blobs R3 deletes, so they go then, as sections rather than as half-working controls.
  `annotationsOf` moved into `PartDetail.tsx` (7 lines) so `lib/annotations.ts` could go whole.
- **`duplicates` left in the Rust `Widget` union** and excluded in the web by type
  (`DrawnWidget = Exclude<Widget, { kind: 'duplicates' }>`), because R3 deletes
  `lapidary-api/src/likeness.rs` and will follow the compiler through `dashboard.rs`. A board
  saved with that widget drops it and keeps the rest.

**For the lead — `FEATURES.md:334` is wrong and this goal is why.** The line says "A user image
does not yet win over the render on a grid card. A blob-backed image cannot reach the grid
without either a 17th column or a card-sized second copy on the row". `GridRow` is a named
`FromRow` struct, so a column is a field; the grid now carries nine more and the picture does win.
Suggested replacement: *"A grid card shows the part's own first image, framed as its row says,
with the rendered thumbnail behind it until R4 purges the renders. The grid carries only inline
bytes, so an image over `INLINE_LIMIT` arrives as a hash and the card emits `/api/blob/{hash}` —
one immutable image load, never a second API request."*
