# A7 — Lapidary runs as the person who installed it

**Status:** open
**Branch:** `feat/run-as-owner`
**Wave:** 12 · **Kind:** deploy + Rust · **Depends on:** A6 · **Migrations:** —

## Why

Owner, 2026-10-17: "User should not need to run custom terminal commands for data access." Lapidary ran as uid 10001,
so every folder of the owner's needed a `setfacl` before the picker could open it.

## Decisions

- The container starts as root only long enough to pick a user, then drops to it with `setpriv` before the server
  starts. The user is `LAPIDARY_UID`/`LAPIDARY_GID` when `deploy/.env` sets them, else **the owner of the `deploy/`
  folder**, mounted read-only for that purpose, i.e. whoever installed Lapidary. The same approach as linuxserver.io's
  PUID/PGID, with the value found instead of typed.
- Never root on a rootful engine: a root-owned checkout falls back to 10001. Under rootless Podman, container root is
  the person, so it is used as it is.
- Lapidary's own folders (the store and the upload staging) are given to that user at start when they belong to
  someone else; the models mount is given over only when it is still owned by 10001, which only Lapidary did.
- The picker's sentences name the uid the server runs as.

## Done when

A fresh install and the owner's install open the owner's folders in the picker with no terminal command; files
Lapidary writes belong to the owner; the rig and the gate pass.

## Record

- `deploy/entrypoint.sh` (the image's entrypoint; `USER` is gone from the Containerfile): `LAPIDARY_UID`/`GID`, else
  the owner of `deploy/` (compose mounts `.:/etc/lapidary/owner:ro`), else 10001; root only under a user namespace
  (rootless Podman), else 10001 with a sentence. It chowns the store and upload staging when they belong to someone
  else, and `/models` while it is still 10001's, then `setpriv --reuid --regid --clear-groups`, no capabilities,
  `no_new_privs`.
- The picker's `setfacl` sentences name the uid the server runs as (`rustix::process::getuid`).
- Rig: `chown_store` hands Lapidary's folders to the rig's own user; the mount guard allows `deploy/` read-only.
  Seed 17 ok, flows 25 ok, the app logging "running as uid 1000". `verify slice`: 14 gates green.
- **Left.** Supplementary groups are cleared, so a folder readable only through a group the person belongs to is not
  reachable; `LAPIDARY_GID` covers one group.
