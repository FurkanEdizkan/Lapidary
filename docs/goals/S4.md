# S4 — Governance, locks and the desktop agent out

**Status:** open
**Branch:** `chore/remove-governance`
**Wave:** 6 · **Kind:** Rust + web · **Depends on:** S3 (both edit `repo.rs` and `lib.rs`'s route list) · **Migrations:** 0057

## Why

The owner decided on 2026-10-16 that a hobbyist and creator library has no checkout, no locks, no lifecycle states
and no approvals. That is `part_lock` and the locks API, controlled-library states and approvals, `lapidary-vcs`
(the figure diff), and `bin/lapidary` — the checkout/checkin agent and its `lapidary://` links.

## Keep

**The `revision` table stays.** It is the row that ties a part to its blob; ingest writes it, downloads are keyed by
it, and a new upload of a part still records a new revision so the old file is not lost. What goes is everything on
top of it. A part's history stays readable on its page.

## Facts to check before building

- What `controlled` turns on: states, approvals, required fields, lock checks in ingest and upload — every branch on
  the library's governance mode in `lapidary-db`, `lapidary-api` and `lapidary-ingest`.
- `crates/lapidary-api/src/revisions.rs` and `locks.rs`; `lapidary-db` `revisions.rs` and `locks.rs` — which parts
  are history (keep) and which are lock/state/approval (go).
- `bin/lapidary`: is anything in it not about checkout/checkin (e.g. `lapidary open`, the folder watch)? Ask the lead
  before deleting something that is not.
- Web: lock badges, state chips, approval dialogs, the governance switch in library settings, their strings.

## Rules

- No user file is deleted. Dropping a lock or a state never touches a blob or a revision.
- 0057 drops `part_lock` and the governance columns/tables; it leaves `revision`.
- CLAUDE.md's versioning and governance rules become "a part keeps its file history; no locks, states or approvals"
  (the lead commits it with the merge).

## Stages

1. Rust and migration. **Tests:** `verify slice` green; uploading a new file for a part records a revision and the
   old one still downloads byte-identical.
2. Web. **Tests:** web tests green; no lock or state appears anywhere.
3. `bin/lapidary` and `lapidary-vcs` deleted. **Tests:** the workspace builds without them.

## Done when

No lock, state or approval exists in schema, API or UI, history still works, and the Record has the lines removed.
