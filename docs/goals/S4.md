# S4 — Governance, locks and the desktop agent out

**Status:** ready, gate log target/verify-S4.log
**Branch:** `chore/remove-governance`
**Wave:** 6 · **Kind:** Rust + web · **Depends on:** S3 (both edit `repo.rs` and `lib.rs`'s route list) · **Migrations:** 0057

## Why

The owner decided on 2026-10-16 that a hobbyist and creator library has no checkout, no locks, no lifecycle states
and no approvals. That is `part_lock` and the locks API, controlled-library states and approvals, `lapidary-vcs`
(the figure diff), and `bin/lapidary` — the checkout/checkin agent and its `lapidary://` links.

## Keep

**The `revision` table stays.** It is the row that ties a part to its blob; ingest writes it, downloads are keyed by
it, and a new upload of a part still records a new revision so the old file is not lost. What goes is everything on
top of it. A part's history stays readable on its page.

## Facts to check before building

- What `controlled` turns on: states, approvals, required fields, lock checks in ingest and upload — every branch on
  the library's governance mode in `lapidary-db`, `lapidary-api` and `lapidary-ingest`.
- `crates/lapidary-api/src/revisions.rs` and `locks.rs`; `lapidary-db` `revisions.rs` and `locks.rs` — which parts
  are history (keep) and which are lock/state/approval (go).
- `bin/lapidary`: is anything in it not about checkout/checkin (e.g. `lapidary open`, the folder watch)? Ask the lead
  before deleting something that is not.
- Web: lock badges, state chips, approval dialogs, the governance switch in library settings, their strings.

## Rules

- No user file is deleted. Dropping a lock or a state never touches a blob or a revision.
- 0057 drops `part_lock` and the governance columns/tables; it leaves `revision`.
- CLAUDE.md's versioning and governance rules become "a part keeps its file history; no locks, states or approvals"
  (the lead commits it with the merge).

## Stages

1. Rust and migration. **Tests:** `verify slice` green; uploading a new file for a part records a revision and the
   old one still downloads byte-identical.
2. Web. **Tests:** web tests green; no lock or state appears anywhere.
3. `bin/lapidary` and `lapidary-vcs` deleted. **Tests:** the workspace builds without them.

## Record

**Done.** Every part keeps its file history, and nothing else is governed. **87 files, +369 / −5,991**
(Rust alone: 43 files, +181 / −4,504).

**Two facts the removal map found, which changed the shape of this goal:**
- **Approvals, lifecycle states and required fields were never built.** All there was is
  `revision.lifecycle_state` from 0002, which nothing read or wrote. It goes in 0057.
- **The hobby path was the one to drop, not the one to keep.** A hobby library answered `Unkept` to a
  changed file and recorded nothing — the opposite of "a part keeps its history". So every library now
  takes what `controlled` used to switch on — the revision path, files set aside under
  `revisions/<label>/` — minus the lock check, and every bundle import replays every revision.

**What went:**
- `part_lock`, `PgLocks`, the three lock routes, `DbError::{PartCheckedOut, LockReleased, UnknownLock}`,
  and the lock on an upload's file and on an `ingest_blob` payload. An old `ingest_blob` row that still
  carries `lock` parses; the key is ignored, and a test says so.
- `LibraryMode`, `library.mode`, `POST /api/libraries/{id}/controlled`, the mode on the library list and
  on a bundle's manifest (an old bundle's `mode` is read and ignored; an old client sending `mode` to
  `POST /api/libraries` still makes a library — both tested).
- `Outcome::Unkept` and the batch's `unkept` count. `job_outcome_known` keeps the word, for `Profiled`'s
  reason: finished rows hold it.
- `GET /api/parts/{id}/diff`, `PartRevision.delta_from_parent`, `lapidary-core`'s `diff.rs` and the whole
  `lapidary-vcs` crate. The history keeps each revision's own figures, mass and centre of mass, and a
  download of its own file.
- `bin/lapidary` — checkout, checkin, `lapidary://` links, `register`, `open`, `agent` and `watch`. The
  owner ruled on `watch` (a folder uploader that took no lock): **the whole binary goes**; the scan folder
  covers it, and the installer phase can bring a desktop helper back. `clap` leaves the workspace with it.
- `RevisionOrigin::Agent` **stays for reading** — existing rows and bundles hold `agent` and `parse`
  refuses unknown words — and nothing writes it.
- Web: the Checked-out row and its release dialog, the comparison panel and the per-revision change
  chips, Open in desktop app, the library mode chooser and the Keep every change switch, and their
  strings and bindings. The History list with a download per revision stays, and its test now asserts
  both files download and nothing asks for a diff.
