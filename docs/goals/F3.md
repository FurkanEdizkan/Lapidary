# F3 — Import from a creator link

**Status:** open
**Branch:** `feat/link-import`
**Wave:** 7 · **Kind:** Rust + web · **Depends on:** S1, S4 · **Migrations:** — (ask the lead if a token table is needed)

## Why

The owner's library is hobbyist models and creator releases, and most of them live on a site first. Pasting the
model's page URL should bring the files, pictures, name, creator and licence in, with the link kept on the part.

## Sites

- **Printables** — public GraphQL; no account for free models.
- **Thingiverse** — REST API with a configured app token.
- **MyMiniFactory** — API v2, OAuth 2.0. Their guidelines say a user must be logged in to download inside a
  third-party app, so the import uses the person's own access token (an API client made in their MMF account
  settings): objects they bought, free objects, and creator releases (ties into P1). Attribution and each object's
  licence must be respected. **The official reference could not be read on 2026-10-16** (403; only an unofficial
  mirror found), so stage 1 confirms the endpoints for object metadata and file download and the scopes needed.
  Pasting a token beats running an OAuth redirect flow; if MMF only issues tokens through the redirect, say so in
  the Record and ask the lead.
- **MakerWorld** — refused by name (Cloudflare; we will not ship FlareSolverr).
- Anything else — refused with a sentence naming the supported sites.

## Facts to check before building

- `crates/lapidary-api/src/fetch.rs` — the SSRF-safe client (resolve-then-pin, manual redirects, whole-fetch budget,
  byte cap while reading). The job runs in the in-process worker after S1; move the client where both can use it.
- `crates/lapidary-api/src/sources.rs` and `part_source` (0015): vendor, url, the seller's id — where creator and
  licence go, and whether a column is missing (ask for a migration number if so).
- The ingest path a staged file takes (`lapidary-ingest`), so imported files hash first like every other file.

## Rules

- Every request goes through the SSRF-safe client, including file downloads and image fetches.
- Files stream to staging, go through ordinary ingest, and staging is removed whether the job fails or not.
- Tokens come from configuration (env or a settings row), are never logged, never returned by the API, never written
  to `metadata.json`.
- `LAPIDARY_IMPORT_LINKS=false` turns the feature off for air-gapped installs: the field is hidden and the API
  refuses with a sentence saying it is off and where to turn it on.
- Errors say what to do: "MyMiniFactory says this object needs to be bought first. Buy it there, then import again."

## Stages

1. Confirm each site's API; write it into Facts. Adapter trait only if three adapters really share a shape —
   otherwise a match on the host.
2. `POST /api/libraries/{id}/imports/link {url}` → job → adapter → staging → ingest → pictures → `part_source`.
   **Tests:** each adapter against recorded responses (no network in tests); refusals for MakerWorld, an unknown
   host, the off switch, a missing token.
3. Web: a paste-a-link field on the library page, job progress through the existing events stream.
4. Live check against one real model per site, recorded in the Record.

## Done when

One real model from each of Printables, Thingiverse and MyMiniFactory lands with files, pictures, creator, licence
and source URL.
