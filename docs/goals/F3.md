# F3 — Import from a creator link

**Status:** ready, gate log target/verify-F3.log
**Branch:** `feat/link-import`
**Wave:** 7 · **Kind:** Rust + web · **Depends on:** S1, S4 · **Migrations:** 0059

## Why

The owner's library is hobbyist models and creator releases, and most of them live on a site first. Pasting the
model's page URL should bring the files, pictures, name, creator and licence in, with the link kept on the part.

## Sites

- **Printables** — public GraphQL; no account for free models.
- **Thingiverse** — REST API with a configured app token.
- **MyMiniFactory** — API v2, OAuth 2.0. Their guidelines say a user must be logged in to download inside a
  third-party app, so the import uses the person's own access token (an API client made in their MMF account
  settings): objects they bought, free objects, and creator releases (ties into P1). Attribution and each object's
  licence must be respected. **The official reference could not be read on 2026-10-16** (403; only an unofficial
  mirror found), so stage 1 confirms the endpoints for object metadata and file download and the scopes needed.
  Pasting a token beats running an OAuth redirect flow; if MMF only issues tokens through the redirect, say so in
  the Record and ask the lead.
- **MakerWorld** — refused by name (Cloudflare; we will not ship FlareSolverr).
- Anything else — refused with a sentence naming the supported sites.

## Facts to check before building

- `crates/lapidary-api/src/fetch.rs` — the SSRF-safe client (resolve-then-pin, manual redirects, whole-fetch budget,
  byte cap while reading). The job runs in the in-process worker after S1; move the client where both can use it.
- `crates/lapidary-api/src/sources.rs` and `part_source` (0015): vendor, url, the seller's id — where creator and
  licence go, and whether a column is missing (ask for a migration number if so).
- The ingest path a staged file takes (`lapidary-ingest`), so imported files hash first like every other file.

## The owner's additions (2026-10-16)

- **A settings page** where a person enters each site's API key and **checks it**: the check calls the
  site with the key and says whether it works. Keys live in the database (0059), not only in env.
- **The 3MF triangle cap goes to 20,000,000** (from 8,000,000): five of the owner's Bambu kits are real
  parts the old cap refused. Its own commit on this branch.
- Built against recorded responses; the live check waits for the owner's keys.

## Rules

- Every request goes through the SSRF-safe client, including file downloads and image fetches.
- Files stream to staging, go through ordinary ingest, and staging is removed whether the job fails or not.
- Tokens come from configuration (env or a settings row), are never logged, never returned by the API, never written
  to `metadata.json`.
- `LAPIDARY_IMPORT_LINKS=false` turns the feature off for air-gapped installs: the field is hidden and the API
  refuses with a sentence saying it is off and where to turn it on.
- Errors say what to do: "MyMiniFactory says this object needs to be bought first. Buy it there, then import again."

## Stages

1. Confirm each site's API; write it into Facts. Adapter trait only if three adapters really share a shape —
   otherwise a match on the host.
2. `POST /api/libraries/{id}/imports/link {url}` → job → adapter → staging → ingest → pictures → `part_source`.
   **Tests:** each adapter against recorded responses (no network in tests); refusals for MakerWorld, an unknown
   host, the off switch, a missing token.
3. Web: a paste-a-link field on the library page, job progress through the existing events stream.
4. Live check against one real model per site, recorded in the Record.

## Done when

One real model from each of Printables, Thingiverse and MyMiniFactory lands with files, pictures, creator, licence
and source URL.

## Record

**Done.** A model comes in from its page: paste a Printables, Thingiverse or MyMiniFactory address into
**Import from a link…** in the library menu, and its STL, OBJ and 3MF files are filed through ordinary
ingest with the page's name, creator, licence, tags and picture. Keys live on a new **Settings** page,
where each one can be checked against its site before it is saved.

**What the research found** (2026-10-16, by request against the live sites from this machine):
- **Printables works end to end with no account.** Public GraphQL at `api.printables.com/graphql/`
  (introspection off; field names proved by trial): `print(id)` for the model, pictures at
  `media.printables.com/` + `filePath`, and `getDownloadLink(id, printId, fileType: stl, source:
  model_detail)` answering an anonymous request with a signed link valid a day. `stls` lists every
  model file, not only `.stl`.
- **Thingiverse and MyMiniFactory answered every request with a Cloudflare challenge** during research
  (`403`, `cf-mitigated: challenge`, file and image hosts included). By the end of the day both APIs
  answered a fake key with a plain refusal instead, which the check reports as such. Their adapters
  follow recorded responses (manyfold's cassettes, MeshDepot's client) and MyMiniFactory's own OpenAPI
  file; a Cloudflare challenge is reported as itself, never as a bad key.
- **MyMiniFactory needs the account's OAuth token, not an API key**: the spec says a file's
  `download_url` is "available ONLY with Oauth connected User", and a key-only response has it `null`.
  So Settings asks for the token, sent as `Bearer` and checked with `GET /user`. **Decided without the
  owner:** a pasted token rather than an OAuth redirect flow — the fewest moving parts, and the goal's
  own preference. **Unchecked:** whether a token gets past MyMiniFactory's Cloudflare from an ordinary
  IP; the owner's first real import will say.
- **MakerWorld is refused by name.** Its pages sit behind the challenge; its design JSON was readable
  but its files need a signed-in browser.

**How it is built:**
- **`lapidary-sites`**, a new L2 crate: `fetch.rs` moved whole from `lapidary-api` (its tests with it)
  and generalised — a method, headers and a JSON body, and **a key is dropped on a redirect to another
  host** (a test proves it) — plus one adapter per site, `identify` (URL → site and id), `Sites::model`,
  `download`, `image` and `check`. `lapidary-api` and `lapidary-ingest` use it; the api still never links
  `lapidary-cad`.
- **0059 `site_key`**: one row per site, plain text with the reason in the migration (a single-owner
  install whose database is theirs). **The API never returns a key** — the list carries its last four
  characters and its last check, and a test asserts the secret is absent from the answer.
- **`import_link`**, a new job kind, runs in the worker: read the model with the saved key, fetch each
  mesh (512 MB cap, whole file in memory as ingest reads it — a `ponytail:` names the upgrade), and
  `index` it under `<site>/<creator>/<model>/<file>` with human-readable names, then give the part a
  `part_source` (page URL, site, model id, title, licence), the page's tags when it has none, and the
  page's first picture when it has none (F1's `adopt_part_image`, origin `url_supplied`). A re-import is
  a re-scan: the same bytes are `skipped`, and the source row is not added twice. Archives, `.f3d` and
  STEP files are skipped and named; a model with nothing else is a refusal that lists what it had.
- **Routes:** `GET /api/settings/sites`, `PUT`/`DELETE /api/settings/sites/{site}`, `POST
  /api/settings/sites/{site}/check` (a typed key is checked without saving it; the saved one's answer is
  recorded), `POST /api/libraries/{id}/imports/link` (refuses an unsupported site, MakerWorld, a non-model
  page or a missing key **before** anything is queued). **`LAPIDARY_IMPORT_LINKS=false`** switches it all
  off: the page says so and every route refuses; compose and `.env.example` carry it.
- **Web:** the Settings page (one row per site: status, a password field, Save, Check, Remove, and where
  the key comes from), a Settings place in the nav, and the import dialog, whose batch shows on the line a
  scan uses with its own wording.
