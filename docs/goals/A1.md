# A1 — Accounts, sign-in and the setup wizard

**Status:** open
**Branch:** `feat/accounts`
**Wave:** 10 · **Kind:** Rust + web · **Depends on:** M5 · **Migrations:** 0063

## Why

Owner, 2026-10-17: several people use one install, set up the way Jellyfin is.

## Decisions

Binding: [`ACCOUNTS.md`](ACCOUNTS.md), the plan the owner approved on 2026-10-17. Read the sections this goal names
before writing code.

## Done when

A fresh install answers `setup_required` until the wizard (setup code from the log, admin account, server facts, options) has run; every other `/api` route needs a session; the existing parts belong to the admin; `reset-password` works through `docker compose exec`.

## Record

- **Schema (`0063`).**
  - `app_user` stores an argon2id PHC string; `username` is case-folded, and a check constraint keeps it that way.
  - `session` keeps a token's BLAKE3 hash only. Sessions last 30 days and slide forward, with at most one write an hour.
  - `instance_setting` holds `setup_code` (its hash) and `import_links`.
  - `library.owner_id` and `part.owner_id` are nullable until A3.
  - `profile` stays, so the wizard can offer its name; A3 drops it.
- **API (`auth.rs`).**
  - `router()` mounts `/api/setup` and `/api/session` in the open; everything else sits behind `require_user`, applied with
    `route_layer`, so an unknown path is still a plain 404.
  - `/api/events` has its own guard (`events::router(hub, db)`).
  - `same_origin` refuses a non-GET request whose `Origin` names another host.
  - `POST /api/setup` locks `app_user`, makes the admin, claims every library and part without an owner, and spends the
    code, all in one transaction.
  - A wrong password or code costs 1 s.
  - `profile` is per person now (`app_user.display_name`).
  - The import switch is `LAPIDARY_IMPORT_LINKS=false` (forces it off) or the wizard's setting.
- **Server.**
  - At start-up, while nobody has an account, the server logs `setup_code=…`. `LAPIDARY_SETUP_CODE` (passed through compose)
    replaces it.
  - `lapidary-server reset-password <user>` prints a new password and ends that person's sessions.
- **Web.**
  - The root route's `beforeLoad` asks `session.gate`: `/setup` while nobody has an account, `/login` while signed out.
    A signed-in answer is remembered for the page's life.
  - `watchSession` wraps `fetch` once and sends a person to sign in when any `/api` answer says the session ended,
    so none of `api.ts`'s ~53 calls changed.
  - The wizard has three steps (account, server facts, options). Sign-in is one page. The user menu has Sign out.
  - Page tests stub the gate through `src/test-setup.ts`.
- **Tests.**
  - Every API test signs in through `tests/common::router`, which makes a real account and session row and sends its
    cookie. There is no bypass in the crate.
  - `tests/auth.rs` covers:
    - setup once, with a wrong code, with the code typed loosely, the claiming and the import switch;
    - sign-in, sign-out, and `set_password` ending sessions;
    - the cross-site refusal.
  - The server's router test signs in through the real setup.
- **Rig.**
  - `stack.sh` writes `LAPIDARY_SETUP_CODE=E2E-RIG-SETUP`. `sign_in_rig` runs setup, or signs in, into a cookie jar that every
    `curl` sends. The flows' and `open-timing`'s browsers get the cookie over CDP.
  - On a fresh stack, `/` lands on the wizard. Seed: 17 checks ok. Flows: 25 ok, after `part-detail` was changed to wait for the
    part's own sections rather than the header's h1, a race the session check made visible.
  - A real Chrome session: a wrong password shows the server's sentence, the right one lands on the grid, and Sign out goes to
    `/login`, after which the API answers 401.
  - `verify slice`: 14 gates green.
- **Left.**
  - A Settings toggle for the import switch (the wizard sets it once).
  - Users, admin pages and the per-user library are A4's.
  - Ownership is enforced in A3.
