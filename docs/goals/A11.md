# A11 — The viewer reads models off the page's thread

**Status:** open
**Branch:** `feat/viewer-worker`
**Wave:** 12 · **Kind:** web · **Depends on:** A10 · **Migrations:** —

## Why

Owner, 2026-10-18: viewing an uploaded Bambu Studio project (`Industrial_Interior_Set_E.3mf`, 42 MB, 234 MB unpacked)
froze the screen and then failed to load. three's `ThreeMFLoader` ran on the main thread for 10 s and then threw
`Maximum call stack size exceeded`.

## Decisions

- View still draws the original file (the rule stands); it is read in a Web Worker, so the page never freezes.
- `meshPositions(format, bytes)` turns any of the three formats into flat triangle positions in millimetres: three's
  loaders for STL and OBJ, and for 3MF a reader of our own that follows `lapidary-cad/src/tmf.rs` — the model part
  through `_rels/.rels`, `p:path` components, build and component transforms, the unit, a depth limit — scanning the
  XML instead of building a DOM. `fixtures/bbox-mm.json` holds it to the server's figures.
- A model too large to draw in a browser says so and offers the download.

## Done when

The owner's file views without freezing the page; the bbox and unit tests pass through the new reader; the gate and the
rig pass.
