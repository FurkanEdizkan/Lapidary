# A11 — The viewer reads models off the page's thread

**Status:** merged
**Branch:** `feat/viewer-worker`
**Wave:** 12 · **Kind:** web · **Depends on:** A10 · **Migrations:** —

## Why

Owner, 2026-10-18: viewing an uploaded Bambu Studio project (`Industrial_Interior_Set_E.3mf`, 42 MB, 234 MB unpacked)
froze the screen and then failed to load. three's `ThreeMFLoader` ran on the main thread for 10 s and then threw
`Maximum call stack size exceeded`.

## Decisions

- View still draws the original file (the rule stands); it is read in a Web Worker, so the page never freezes.
- `meshPositions(format, bytes)` turns any of the three formats into flat triangle positions in millimetres: three's
  loaders for STL and OBJ, and for 3MF a reader of our own that follows `lapidary-cad/src/tmf.rs` — the model part
  through `_rels/.rels`, `p:path` components, build and component transforms, the unit, a depth limit — scanning the
  XML instead of building a DOM. `fixtures/bbox-mm.json` holds it to the server's figures.
- A model too large to draw in a browser says so and offers the download.

## Done when

The owner's file views without freezing the page; the bbox and unit tests pass through the new reader; the gate and the
rig pass.

## Record

- `mesh.ts`: `meshPositions` (nine floats a triangle, millimetres), `meshFrom`, `parseMesh` (both on this thread, for
  tests), `loadMesh` (a module worker per load, the bytes and the positions transferred, ended on answer or abort;
  inline where there is no `Worker`). three's `ThreeMFLoader` is gone; the 3MF reader follows `tmf.rs` and scans each
  model part in 64 MB slices ending on `>` (one real model part passes JavaScript's 512 MB string limit), with fast
  paths for `x y z` and `v1 v2 v3`. 50 million triangles at most, said in a sentence (`ponytail:`).
- `Viewer.tsx`: `loadMesh` in place of `parseMesh`; the last model drawn is kept by revision, one slot (`ponytail:`).
- Measured on the owner's files. `Industrial_Interior_Set_E.3mf` (42 MB, 234 MB unpacked, 2,791,262 triangles): three's
  loader 10 s on the main thread, then `Maximum call stack size exceeded`; this reader 2.7 s in the worker, at the
  server's box to the hundredth of a millimetre. All 89 real 3MFs in the corpus come out at the box `lapidary-cad`
  measures for them, `Questoris_V2.3mf` (11.5 million triangles) in 12.6 s; three's loader ran out of memory on
  `Mortar_Turret.3mf` and of stack on others.
- Checks: `mesh.test.ts` (the bbox fixtures and units through the new reader, a `p:path` component with its
  transforms, slices never cutting a tag), `Viewer.test.tsx`. Rig: seed 17 ok, flows 26 ok, `view-original` drawing in
  headless Chrome through the worker.
- **Left.** A very large model still takes seconds to read; the page stays usable and says it is loading. A
  model is read again after another one has been viewed.
