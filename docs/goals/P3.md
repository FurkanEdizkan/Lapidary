# P3 — Tags as places

**Status:** open
**Branch:** `feat/tag-browse`
**Wave:** 3 · **Kind:** web (+ a small read) · **Depends on:** W0 · **Migrations:** —

## Why

Tags are how anybody actually browses a model library — "dragon", "terrain", "bracket" — and ours are a filter and
nothing more: `PUT /api/parts/{id}/tags` writes them, the facet counts them within the current grid, and there is no way
to ask "what tags does this library have" or to land on one. A tag a person cannot navigate to is a tag they will not
use.

## Facts to check before building

- The tags facet in `GET /api/libraries/{id}/facets`: it counts **within the current grid** and past
  `EXACT_FACET_ROWS` it lists values without counts. A tag index wants the whole library, which may be a different read.
- `part.tags` is a text array with a GIN index (`0022_part_tags.sql`); co-occurrence is one query over it, not a new
  table.
- The grid's `tag=` parameter and how the URL, the saved filters and the back button already handle it.
- `web/src/lib/strings.ts` — this goal's own top-level block; no other goal's is touched.

## Rules

- **No tag table.** Tags live on the part; an index is a read.
- A tag page **is** the grid pre-filtered, the same component and the same URL parameter — not a second grid.
- Related tags are earned from co-occurrence, with a floor (a tag sharing one part is not "related"), and the floor is
  stated in the UI's words.

## Stages

1. **The read** — a library's tags with counts over the whole library, and the tags most often on the same parts as a
   given tag.
   **Tests:** counts match the facet's when no filter is applied; a tag on no live part is absent; a removed part's tags
   do not count.
2. **The pages** — `/tags` (by count and by name, with a letter jump when the list is long) and `/tags/{tag}` (the grid,
   pre-filtered, with related tags beside it and an empty state that says the tag is gone).
   **Tests:** each with `fetch` mocked; the title is the tag; a tag with punctuation or a space survives the round trip
   through the URL.
3. **The chips lead somewhere** — tags on the part page and in quick look become links to their pages, and the grid's
   tag facet row links too, without losing the filter a person already has.

## Done when

Every tag in a library is reachable from `/tags`, a tag page shows the same parts the facet counted, `verify slice` is
green, and the Record says how many tags the seeded corpus produced and how deep the longest list got.
