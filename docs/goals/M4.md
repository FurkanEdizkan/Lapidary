# M4 — Your folders, read where they are

**Status:** open
**Branch:** `feat/index-in-place`
**Wave:** 9 · **Kind:** Rust + deploy · **Depends on:** M3 · **Migrations:** 0062

## Why

Owner, 2026-10-17: do not ingest into a storage location of ours; use each file's own path. A scan
records where a file is and reads it there — **never copies, renames, moves or writes into the owner's
folders** (no `metadata.json`, no `revisions/` directory). Uploads and link imports are written once into
an **inbox folder** the owner chooses, then indexed like any other file.

## Consequences, said up front

- A category is the library's own grouping; moving a part between categories moves nothing on disk.
- A changed file is still a new revision, but only its figures and hash are remembered: the old bytes
  were the owner's file, overwritten by them, and Lapidary keeps no copy.
- Pictures and exports Lapidary makes still live in its own store, which is ours, not the owner's.

## Decisions (lead, 2026-10-17, from the read-only map of the code)

- **Roots.** `library.root`: a path under the ingest mount (`''` = the whole mount for the default library),
  checked with `path_escapes`. A scanned file's `source_path` stays relative to its library's root.
- **Every file row names its root**: a `file.root` column — `library` (the owner's folders, mounted `:ro`),
  `inbox` (Lapidary writes here, once), `store` (rows from before M4, still read from the blob root where they
  are; never moved, never deleted). NULL keeps meaning nothing new.
- **The inbox lives outside the owner's folders** (`LAPIDARY_INBOX_DIR`, mounted rw at `/inbox`): uploads to
  `uploads/<relative path>` (never overwriting — a collision takes a disambiguated name), link imports to
  `imports/<site>/<creator>/<model>/<file>` (Lapidary's own subtree: a re-import may replace its own file, which
  is a new revision), the examples copied in once by the seed.
- **Change detection**: size and mtime recorded at index; a download pre-flights them and refuses with a sentence
  ("this file changed in your folder since Lapidary last read it — scan again") before a byte is sent; the
  end-of-stream hash stays.
- **Revisions without copies**: `file.on_disk`; a changed file is a new revision and the old row is marked not on
  disk. History shows "no longer on disk" instead of a link; the route answers 410. Bundle import records older
  revisions rows-only.
- **Removed outright**: copying into the store, `metadata.json` and `DescribePart`, `revisions/<label>/`,
  `migrate_storage`, moves on disk (a move is a database change), source compression, `SourceWriter`,
  `SourceRelocator`, `IngestBlob`, the reaper's model-file half. Nothing may unlink an owner file; owner roots are
  mounted `:ro` as the backstop.
- **CLAUDE.md** loses "the one before it stays on disk and downloadable" and qualifies "byte-identical" with
  "as long as the file on disk has not changed since it was indexed" (lead edits it at merge).
- **The rig** snapshots the ingest tree before and after scan, move, revision and upload and asserts nothing
  under it changed.

## Done when

Scanning the owner's corpus writes nothing under it; downloads read the original path; the inbox works for
uploads and imports; the rig passes.
