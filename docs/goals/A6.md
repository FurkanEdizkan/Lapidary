# A6 — The models folder, chosen in the wizard and Settings

**Status:** open
**Branch:** `feat/models-folder-picker`
**Wave:** 12 · **Kind:** Rust + web + deploy · **Depends on:** A5 · **Migrations:** —

## Why

Owner, 2026-10-17, on the wizard's server step: "these can be configurable from here as well". A container cannot
change its own mounts, so compose mounts one browse root (owner's choice: the whole machine, `/`) at `/host`, and the
wizard and Settings choose the models folder inside it. Lapidary restarts itself to use it.

## Decisions

- `LAPIDARY_BROWSE_ROOT` (default `/`) is mounted read-write at `/host` with **no** SELinux relabel option, because
  relabelling `/` would relabel the machine. Writes stay limited to what uid 10001 may write.
- The models folder is `instance_setting.models_dir`, a host path, saved by `PUT /api/settings/storage` (admin only).
  `LAPIDARY_MODELS_DIR` or `LAPIDARY_INGEST_DIR` set in `deploy/.env` fixes the folder, and Settings says so, the same
  way `LAPIDARY_PORT` fixes the port. With neither set and nothing saved, the `/models` mount is used as before.
- Choosing a folder never orphans a model. Files Lapidary wrote under its own folders (`examples/`, `uploads/`,
  `imports/`) are copied to the same place in the new folder; a model added from the current folder, or an added
  source, refuses the change with a sentence.
- `/host` itself, `/proc`, `/sys`, `/dev` and `/run` can't be chosen. Writability is checked with `access(W_OK)`;
  nothing is created to probe it.
- Saving restarts the process (`restart: unless-stopped`), and the page waits behind the app skeleton.
- Lapidary's own files (the picture store) stay a fact: moving them would break every download.

## Done when

The wizard and Settings › Server pick the models folder from a folder browser; the app restarts on it, signed in;
existing models still download; a fixed folder is locked with its sentence; "Uploads and imports" is gone and the
store shows a real place.

## Record

- **compose.** `${LAPIDARY_BROWSE_ROOT:-/}:/host` (read-write, no relabel), `LAPIDARY_HOST_DIR=/host`,
  `LAPIDARY_HOST_BROWSE_ROOT`, and `restart: unless-stopped`. `LAPIDARY_HOST_INGEST_ROOT` is now
  `${LAPIDARY_MODELS_DIR:-}`, so set means fixed; `LAPIDARY_INBOX_DIR` and its host root are gone (the inbox is the
  folder in use).
- **`bin/lapidary-server/src/models_dir.rs`.**
  - `first()`: fixed by `LAPIDARY_MODELS_DIR`, else `instance_setting.models_dir` mapped into `/host`, else the
    `/models` mount.
  - `GET/PUT /api/settings/storage` and `GET /api/settings/storage/folders` (admin), plus `/api/setup/storage` and
    `/api/setup/storage/folders`, which answer only with the setup code while nobody has an account.
  - The picker hides symlinks, dot-folders and `_removed`, refuses the root, `/proc`, `/sys`, `/dev`, `/run`, `..` and
    escapes, and names the `setfacl` line for a folder uid 10001 can't open or write (`access(W_OK)` via rustix,
    already in the lock).
  - A change is refused while models are read in place from the current folder or anything was added from it;
    files under `examples/`, `uploads/`, `imports/` are copied with their modified times (a download compares
    them), never over a different file, and nothing is removed. Then the setting is saved and the process stops
    so compose starts it again.
- **Web.** `FolderPicker.tsx`; the wizard's server step chooses the folder (applied after the account, with the
  port), drops "Uploads and imports", and shows where the store is; Settings › Server has the same, behind
  `AppSkeleton` while `followRestart` waits for the server to leave and come back.
- **Checks.** Unit tests for host-path mapping, the choice's refusals and the copy. Live, a throwaway compose project
  on lane 1's ports with a scratch browse root: 21 of 21 (code-gated setup routes, listing, refusals, setup, the
  restart onto the chosen folder signed in, the examples copied and still downloading, Import browsing the new
  folder, and a second change refused once a folder was added). `verify slice`: 14 gates green.
- **Left.** Choosing the folder needs uid 10001 to traverse every folder above it; the owner's drives are `700`,
  so they need `setfacl -m u:10001:x` on each, which the picker says. Running as the host user instead is the
  upgrade if that is too fiddly. Lapidary's own files are shown, not chosen.
