# A6 — The models folder, chosen in the wizard and Settings

**Status:** open
**Branch:** `feat/models-folder-picker`
**Wave:** 12 · **Kind:** Rust + web + deploy · **Depends on:** A5 · **Migrations:** —

## Why

Owner, 2026-10-17, on the wizard's server step: "these can be configurable from here as well". A container cannot
change its own mounts, so compose mounts one browse root (owner's choice: the whole machine, `/`) at `/host`, and the
wizard and Settings choose the models folder inside it. Lapidary restarts itself to use it.

## Decisions

- `LAPIDARY_BROWSE_ROOT` (default `/`) is mounted read-write at `/host` with **no** SELinux relabel option, because
  relabelling `/` would relabel the machine. Writes stay limited to what uid 10001 may write.
- The models folder is `instance_setting.models_dir`, a host path, saved by `PUT /api/settings/storage` (admin only).
  `LAPIDARY_MODELS_DIR` or `LAPIDARY_INGEST_DIR` set in `deploy/.env` fixes the folder, and Settings says so, the same
  way `LAPIDARY_PORT` fixes the port. With neither set and nothing saved, the `/models` mount is used as before.
- Choosing a folder never orphans a model. Files Lapidary wrote under its own folders (`examples/`, `uploads/`,
  `imports/`) are copied to the same place in the new folder; a model added from the current folder, or an added
  source, refuses the change with a sentence.
- `/host` itself, `/proc`, `/sys`, `/dev` and `/run` can't be chosen. Writability is checked with `access(W_OK)`;
  nothing is created to probe it.
- Saving restarts the process (`restart: unless-stopped`), and the page waits behind the app skeleton.
- Lapidary's own files (the picture store) stay a fact: moving them would break every download.

## Done when

The wizard and Settings › Server pick the models folder from a folder browser; the app restarts on it, signed in;
existing models still download; a fixed folder is locked with its sentence; "Uploads and imports" is gone and the
store shows a real place.
