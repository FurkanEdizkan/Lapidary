# F2 — A stable file link

**Status:** open
**Branch:** `feat/stable-file-link`
**Wave:** 7 · **Kind:** Rust + web · **Depends on:** S4 · **Migrations:** —

## Why

A download today is `GET /api/revisions/{id}/download?variant=original`, keyed by revision, so a copied link goes
stale the moment a new file is recorded. People want one link per part that always gives the current file — to paste
into a slicer, a chat, a script.

## Facts to check before building

- `crates/lapidary-api/src/download.rs` (1,147 lines): headers it sets, whether it already answers `Range`, how it
  hashes on the way out, how it names the file.
- How "the part's current revision" is read today (the part page shows one).

## Rules

- `GET /api/parts/{id}/file` serves the current revision's **original** bytes through the same code path as
  `variant=original` — never a conversion.
- `Content-Disposition: attachment; filename*=UTF-8''<original name>`. Range answers 206 with a correct
  `Content-Range`; a range on a hash-checked stream is allowed to skip the outgoing hash check for that request, and
  the code says so.
- Access is what it is today: whoever reaches the port. FEATURES.md says it in those words.

## Stages

1. The route. **Tests:** full body byte-identical (BLAKE3) to the ingested file; `Range: bytes=0-99` gives 206 and
   100 bytes; after a new revision the same URL gives the new file.
2. "Copy link" on the part page and the card menu. **Tests:** web test.

## Done when

`curl -r 0-99` and a full `curl | b3sum` both check out against a real stack.
