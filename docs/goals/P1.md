# P1 — Creator releases and packs

**Status:** open
**Branch:** `feat/release-import`
**Wave:** 4 · **Kind:** Rust (ingest) · **Depends on:** G2, L3 (all three touch the worker's dispatch) · **Migrations:** 0053

## Why

The owner's corpus is shaped like the archive sites this product is measured against: `/mnt/Storage2/All/STL Files` holds
54 creator directories of monthly releases — **379 `.zip`, 159 `.tar.xz`, 137 `.rar`, 113 `.7z`** (counted 2026-09-26 to
depth 6) and 1,513 loose model files. Today the archives are unreachable: `POST /api/libraries/{id}/imports` reads only
**our own** bundle, a ZIP carrying `manifest.json` (`crates/lapidary-ingest/src/import.rs`,
`lapidary_targets::bundle::Bundle::open`), so a creator's pack is refused for want of a file it was never going to have.
A library that cannot take a release cannot be the index for a library like this one.

A release is also the unit people think in — "Nomad Gods, Pilgrimage, March 2025" — so it is worth recording as a thing,
not flattened into a folder name.

## Facts to check before building

- `lapidary_targets::bundle` — what its ZIP reader refuses, and whether a manifest-less archive can reuse it or needs a
  second reader.
- `crates/lapidary-ingest/src/handler.rs` — where `ImportPart` and `ImportBundle` dispatch, and what G2's `ProfileShape`
  and L3's re-derive path did to that match (this goal follows both).
- `lapidary_core::path_escapes` — already the refusal for a path climbing out of its root; a zip-slip guard should be it,
  not a second implementation.
- The scan rules for what is a model file and what is ignored (`is_model_file`, `is_ignored`), so an archive's readmes,
  renders and `.lys` files are skipped by the same rules a directory scan uses.
- `job_outcome_known` — this goal's outcome word (`imported` exists? if not, 0053 widens it as `0047` did).

## Rules

- **Never a second definition of what a model file is.** An archive is a directory that happens to be compressed.
- Refusals say what to do: "This archive holds no model file we read. It may be a render pack or a `.rar`, which we do
  not open yet."
- Nothing is extracted into the store. Members stream to a staging directory, are ingested by the ordinary path, and the
  staging directory goes away — failed or not (the staging leak L2 fixed on the sharing side is the same mistake).
- Caps stated and tested: member count, uncompressed total, and a refusal before a single byte is written.

## Stages

1. **The release row** (`0053`): `release (id, library_id, name, creator, blake3, source_path, imported_at, part_count)`
   and a link from each part to the release it arrived in, deleted with the part by `PgParts::purge` and covered by the
   catalogue test. Repository reads: a library's releases, one release's parts, a part's release.
2. **ZIP without a manifest** — 379 of the corpus's archives, and the reader exists. One job per archive: open, list,
   refuse early on the caps or on a path that escapes, stream each model member to staging, ingest it into a folder
   named for the release, record the row, report what was skipped and why.
   **Tests:** a real corpus archive (copied, the corpus stays read-only) imports and its parts carry the release; a
   zip-slip member is refused and nothing is written; an archive of renders only is refused in words; a second import of
   the same archive is `skipped` on its hash.
3. **Tar** — `.tar`, `.tar.gz`, `.tar.xz` (159 more) behind two pinned crates, through the same job and the same caps.
   **Tests:** the same four, plus a `.tar.xz` whose member names carry spaces and parentheses (the corpus's do).
4. **The part page says where it came from** — the release name, the creator, and the archive's name, read from the new
   rows. No new UI beyond that line; browsing by release is P2's and P4's.

## Recorded, not built

- **`.rar` (137) and `.7z` (113).** Both want a new dependency or a host tool in the worker image, and `unrar`'s licence
  is the owner's decision, not a lane's. The refusal names the format so the count is visible.
- Nested archives (an archive inside an archive) are refused, not recursed.

## Done when

A real creator release from the corpus imports, its parts carry it, the caps and the zip-slip guard are tested,
`verify slice` is green, and the Record says how many of the corpus's 788 archives are now reachable.
