# A14 — MyMiniFactory answers to its API key

**Status:** claimed
**Branch:** `fix/mmf-api-key`
**Wave:** 12 · **Kind:** Rust + web · **Depends on:** A13 · **Migrations:** —

## Why

Owner, 2026-10-18: Fetch details on a MyMiniFactory link failed with "MyMiniFactory refused the key". The saved
secret is an API key (the kind MyMiniFactory's developer settings hand out). Probed live with it: the API answers
`?key=<key>` with the object (name, description, pictures at 1000×1000, tags, licence, categories, designer, file
names and sizes) and answers the same key sent as `Authorization: Bearer` with 401. `/user` needs an OAuth token,
so the key check failed too. The module's "Cloudflare blocks us" note was curl's TLS fingerprint, not the site.

## Decisions

- The secret goes as `?key=` first; a 401 retries it as `Bearer`, so an OAuth token still works (and still
  downloads). The check asks `/categories` with `?key=`, which refuses a bad or missing key, then `/user` as a token.
- A key in a query string must never reach an error: reqwest's error text drops its URL (`without_url`).
- A file's `size` arrives as a string; it is read either way.
- An API key gives details and pictures, never a download link (`download_url` is null); Settings says so.

## Done when

Fetch details on `…/3d-print-trench-crusade-lieutenant-new-antioch-420952` with the owner's API key gives the
model's pictures, tags, licence and creator; the key check passes; a token still downloads in the fixture test; the
gate passes.
