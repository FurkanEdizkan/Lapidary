# G5 — Dashboard UI

**Status:** open
**Branch:** `feat/dashboard-ui`
**Wave:** 2 · **Kind:** web · **Depends on:** W0 · **Migrations:** —

## Why

The roadmap's first Phase 6 exit: a 12-widget dashboard settles in one round trip, and stays current without anybody
polling. Design: [`phase-6.md`](phase-6.md) § Dashboard.

## Facts checked (re-check against W0's merge)

- W0's bindings: `Widget` (seven kinds), `ResolveRequest`, `ResolveResponse`, `KeyResult`, `AppEvent`; the
  `dashboard` block in `strings.ts`; `titles.dashboard`.
- The backend is G4 (resolve) and G1 (events), built in parallel: develop with `fetch` and `EventSource` mocked.
- Per-browser precedent: `web/src/lib/preferences.ts`. Motion: `web/src/lib/flip.ts`, `web/src/lib/motion.ts`.
  Nav: `web/src/components/AppFrame.tsx` (Parts, Removed, Sharing today).

## Rules

- Owns: `web/src/routes/dashboard.tsx` and its test; `web/src/components/dashboard/*` (`Board.tsx`, `layout.ts` and its
  test, `registry.tsx`, `widgets/*.tsx` including duplicates, `AddWidget.tsx`); `web/src/lib/{dashboard,events}.ts`
  and their tests; `AppFrame.tsx`'s `Place` and nav link; the `dashboard` strings block. FEATURES §8 and
  ARCHITECTURE's layout row go in the Record for the lead.
- **No `refetchInterval` under the dashboard's files** — a test says so. One request per load: the resolve.

## Stages

1. **Layout** (`layout.ts`, pure): 12 columns, collisions, vertical compaction, size limits per kind, keyboard move
   (arrows) and resize (Shift+arrows). Tests for each.
2. **Board and registry** — `Record<Widget['kind'], WidgetSpec>`; drag and resize with pointer capture; `aria-live`
   says where a widget went; `flip.ts` motion (180 ms, transform only, reduced motion respected); named groups as
   titled `<section>`s, moved between and reordered through menus; layout saved in localStorage
   `lapidary.dashboard` v1.
3. **Widgets** — the seven kinds; a `timedOut` key shows its own retry while the others render.
4. **Live** — `useAppEvents`: one shared `EventSource` per tab; `changed{A}` re-resolves only library A's keys, in one
   call, at most once a second; `resync` re-resolves everything.
5. **Tests:** mounting 12 widgets makes exactly one fetch, to `/api/dashboard/resolve`; the timed-out key; the event
   rules; no `refetchInterval`; title, roles, contrast, no bare strings.

## Done when

Web tests green, handed off; the lead merges after G4 and G1.

**Phase exit 1 (measured by the lead after merge):** in a browser against a stack, a 12-widget dashboard shows one
resolve request in the network log and settles (time recorded); an upload updates the storage and recent widgets
through one re-resolve.

## Record

Web only; no Rust changed. Built against W0's bindings with `fetch` and `EventSource` mocked, so
nothing here has yet spoken to a running server — the live check is the lead's phase exit, after G4
and G1 merge. What *was* looked at in a browser is the layout: the built page was served on lane 3's
port 33000 against a fixture api and photographed at 1440 and at 390 (below).

- **`web/src/lib/dashboard.ts`** (new) — the one request and the stored arrangement. `resolve()`
  (`POST /api/dashboard/resolve`, refusing a 200 without a `results` list, the guard `fetchFolds`
  already makes), `byKey`, `requestOf`, `libraryOf` (exhaustive over the Rust union, so an eighth
  kind fails `tsc` here too), and the `localStorage` half: `readLayout`/`writeLayout`/`sanitise`
  under `lapidary.dashboard`, version 1, every access wrapped as `preferences.ts` argues.
  **`sanitise` is the trust boundary that matters**: the resolve route refuses a body *whole* with a
  422, so one unreadable entry would blank all twelve panels rather than its own. Anything it cannot
  rebuild is dropped, a `limit` past the cap is corrected, a widget whose group has gone moves home
  rather than vanishing, and the list is cut to 32. `nextKey` counts rather than calling
  `crypto.randomUUID()`, which **exists only in a secure context** — an air-gapped install reached
  over plain `http://10.0.0.7:8080` has none, and Add would have thrown on exactly the deployments
  this product is for.
- **`web/src/lib/events.ts`** (new) — `useAppEvents`, one reference-counted `EventSource` per tab,
  closed when the last subscriber leaves. The first `open` is **not** a resync (that would cost every
  page load a second resolve, and two under StrictMode); a later one is, because a reconnect carries
  no history. Changes coalesce to at most one delivery a second **on the trailing edge** — a
  leading-only throttle delivers the first notification of an upload and drops the last, which is the
  one that says the batch finished. No `error` handler resyncs: the browser reopens by itself.
- **`web/src/components/dashboard/layout.ts`** (new, pure) — 12 columns, collision, vertical
  compaction, clamping, keyboard move and resize, and the two pixel-to-cell functions. Generic over
  anything carrying `{key,x,y,w,h}`, so it imports nothing — not the registry, not `strings.ts`, not
  React — and takes the size limits as an argument.
- **`web/src/components/dashboard/registry.tsx`** (new) — `{ [K in Widget['kind']]: WidgetSpec<K> }`:
  the `Record` keyed off the Rust union that `phase-6.md` fixes, written as a mapped type so each
  entry's renderer is typed against *its own* value rather than the whole union. `drawValue` is a
  second exhaustive point (a `never` at the end), and `limitsOf` is how `layout.ts` gets the sizes
  without knowing this file exists.
- **`web/src/components/dashboard/widgets.tsx`**, **`Board.tsx`**, **`AddWidget.tsx`** (new) — the
  seven bodies, the grid, and the forms. `Board` holds the drag (pointer capture, guarded the way
  `flipFrom` guards `animate`), the arrow keys, the corner, the `aria-live` region, the named
  groups, and the motion.
- **`web/src/routes/dashboard.tsx`** (new) — `/dashboard?library=`, titled, and the fourth place in
  `AppFrame`.
- **Shared files touched, flagged for the lead:** `web/src/lib/types.ts` (twelve re-exports, appended
  as one contiguous block the way G6's was), `web/src/lib/flip.ts` + its test (see below),
  `web/src/components/AppFrame.tsx` (`Place` gains `dashboard`, and the nav a fourth link — G5.md
  names both), `web/src/lib/strings.ts` (the `dashboard` block, 63 entries; no other block touched),
  `web/src/routeTree.gen.ts` (regenerated). **Nothing was added to `lib/api.ts`** — the lead's note
  about lane 4 holding its sharing helpers; the two reads the Add form needs are imported, not
  changed.

### Decided without the owner

- **`flipFrom` gained an optional duration, defaulting to what it had.** It hard-coded
  `--duration-slow` (280 ms) and `phase-6.md` names 180 ms for a widget changing places — which is
  also what `DESIGN.md` caps a state change at, as `flip.ts`'s own comment says. A second FLIP under
  `components/dashboard/` would have been a second place for the reduced-motion and zero-area
  declines to be forgotten, so the argument was added instead and every existing caller is unchanged.
  One new test in `flip.test.ts` pins both durations.
- **Vertical position is derived, never stored as a choice.** `settle()` computes every row from the
  widgets' *order*, so the board cannot hold a gap and no caller has to remember to compact. The
  consequence is that **arrow up and down are reorderings**: on a compacted board `y + 1` is undone
  by the next settle, so "down" has to mean *past the widget below me*. A widget with nothing in its
  columns cannot move that way, which is also the truth — it is already as high as the board goes.
- **One file for the seven widget bodies**, not seven, for the reason `Likeness.tsx` gave: each is a
  paragraph or a short list, and seven files of eight lines would put the shared row in whichever was
  written first.
- **The settings form is declared, not drawn seven times.** `WidgetSpec.fields` names which of four
  controls a kind offers and `AddWidget.tsx` renders them, so Add and Settings are one form. Seven
  form components would be seven spellings of "which library", and the eighth Rust kind would ship
  with a form somebody forgot rather than a `tsc` error.
- **`facet`'s `limit` is capped at 12, the same as `recent` and `savedFilter`.** The design gives
  `facet` no cap and W0 says G4 enforces the other two; one ceiling a person can learn is better than
  two. **G4 should confirm it caps `facet` at the same number or say what it does cap.**
- **A widget stores its library's *name*, snapshotted when it was added.** No `WidgetValue` but
  `FilteredParts` names its library, so two storage panels for two libraries are otherwise the same
  panel twice — and reading `/api/libraries` on load would be the second request this page does not
  have. It goes stale on a rename, which is precisely what `FilteredParts.name` exists to avoid, so
  a saved filter's heading uses the name the server just sent instead. **A `library` name on the wire
  would close it; it is the lead's and G4's call.**
- **A `changed{A}` re-resolves library A's keys *and* every whole-store widget.** A part added
  anywhere moves `InstanceStorageView`'s figures and no notification says "the installation changed";
  by the letter of the design only a `resync` would refresh it, and it would then be wrong until one
  arrived. One call for the lot.
- **`refetchOnMount: 'always'`, which is not a timer.** The `QueryClient` is the application's and
  holds this key for five minutes after the page is left, so coming back inside that window would
  otherwise show the previous visit's answer with no request — and a widget added during that visit
  would sit on "Loading" for ever, because its result only ever lived in component state. Each
  arrival asks once, for the layout as it is now. `staleTime: Infinity` and `refetchOnWindowFocus:
  false` stay: refetch-on-focus is polling on a schedule set by how often somebody looks at the
  window, and a test now holds both off.
- **The corner is a real button in the tab order**, and its arrow keys resize without Shift. The
  grip's Shift+arrow is the same action from the header; a corner no keyboard can reach is the half
  of a hand-rolled resize WCAG is about.
- **Focus is asked for by name after a keyboard move.** Moving *down* reorders the group, and React
  reconciles a reorder by relocating the widget's node, which takes focus off the grip inside it.
  Moving up relocates the other node, so the loss is one-directional — the kind of bug nobody
  reproduces. Held by a test that focuses the grip, presses Down, and reads `document.activeElement`.
- **A facet widget's heading names its facet** (Formats / Materials / Tags), not its kind. Found in
  the 1440 pass: a board with all three read "Value counts — Fixtures" three times.
- **No mesh figures in the part-list widgets.** `CLAUDE.md` requires every mesh-derived figure to
  carry its "approximate" mark; a widget four rows tall has room for a name *or* a number and its
  label, not both. The way to keep the rule here is not to print one — the part's own page does.
- **Five strings are read from other blocks**, all of them formatters rather than copy:
  `storage.totals`, `storage.everything`, `facets.name`, `facets.format|material|tag`. Two renderings
  of `LibraryStorage` would be two chances to divide the ratio the other way up, which is the thing
  `derivativeRatio`'s doc exists to prevent; `StorageTotals` is reused outright for the same reason.

### Left for later

- **Nothing here has met a server.** Every test mocks `fetch` and `EventSource`. The three things
  G4 and G1 should confirm are above and repeated in the handoff: the `facet` cap, that a `failed`
  result's `message` follows the "what broke and what to do" rule (it is printed verbatim under the
  widget), and whether a library's name can ride on the wire.
- **A widget's position is written to `localStorage` on every drag frame that changes a cell.** A few
  writes per drag, wrapped in `try`. A debounce is one line if it ever matters.
- **A partial resolve that fails is silent.** A retry, an event or an added widget that cannot reach
  the api leaves the widgets showing what they had — deliberately, since those figures were right a
  second ago — but nothing says the page has stopped following. The first load's failure does say so.
- **No per-widget error detail beyond the server's sentence**, and no link from a `failed` widget to
  the thing that failed.
- **The board is one column under `md`, by CSS.** Below 768px the twelve columns and the row height
  are simply not applied, so widgets stack in board order and size to their content. Nobody can drag
  meaningfully at 390 — the keyboard reorder still works. A touch-sized arrangement is a later goal.
- **`layout.ts` has no horizontal compaction.** A widget dragged from the left of a row leaves a hole
  beside its neighbour until something is dropped there. `react-grid-layout` does not do it either.

### What a test cannot see, and what was looked at instead

- **The board has no reading measure**, which is the rig's 1440 finding about `/duplicates` applied
  before it could happen again: `LEAD` keeps its 70ch and the grid does not. jsdom applies no
  stylesheet, so no test can assert it. `target/dashboard-check/dashboard-1440.png` shows the twelve
  widgets across the full window, and `dashboard-390.png` one column with no horizontal scroll.
  Both were taken from the real build through `serve.py` (a fixture api on lane 3's port 33000, the
  arrangement injected into `index.html` before the bundle) and `shots.sh` (headless Chrome, a
  throwaway profile per shot, both under `target/` and not on `/`).
- **The `'base'` flip duration is not mutation-checked.** jsdom implements no `animate`, so `flipFrom`
  declines in every test and the argument `Board` passes cannot be observed. `flip.test.ts` pins that
  `'base'` *is* 180 ms; that `Board` asks for it is held by review only.
- **Pointer capture is guarded, not tested.** jsdom implements none of it.
- **Focus after a keyboard move is a browser fact.** jsdom does not blur an element whose node is
  relocated, so the suite passes whether or not the grip keeps focus, and the mutation for it
  survived. `target/dashboard-check/focus.sh` drives headless Chrome against the same fixture
  server and reads `document.activeElement` after two Downs; it answers
  `focused-before=true after=Move Library storage — Fixtures`.

### Tests

`npm --prefix web test`: **524 pass, 39 files, up from 441/34** at G6's merge. New files:
`components/dashboard/layout.test.ts` (25 — every rule of the packer, plus the invariant "no two
widgets on one cell" asserted after each of four operations on twelve assorted widgets),
`lib/dashboard.test.ts` (17), `lib/events.test.ts` (9), `routes/dashboard.test.tsx` (23),
`components/dashboard/no-polling.test.ts` (3, the source-level guard). Plus one in `flip.test.ts`
and five from the bare-strings gate picking up the new components.

The assertion the goal exists for: **twelve widgets, one `fetch`, to `/api/dashboard/resolve`** —
counted directly, because a render test cannot see a timer that has not fired. Beside it: an empty
dashboard makes *no* request (0 keys is a 422); four moves and a resize make none; returning to the
tab makes none; the first widget on an empty board makes exactly one; a retry asks for one key; a
`changed{A}` asks for A's keys and the whole-store widget in one call.

**Mutation:** `target/dashboard-check/mutate-g5.sh` — **29 mutations, all caught.** Two survived a
run and both were real findings, not harness faults. `refetches-on-focus` survived because the test
dispatched `visibilitychange` on `document` while TanStack Query's focus manager listens on
`window`, so the rule was never being exercised at all. `focus-lost-on-move-down` survived every
test in the suite because **jsdom does not blur an element whose node React relocates** — so it is
not in the harness; the rule is checked in a browser by `target/dashboard-check/focus.sh`, which
focuses the first grip, presses Down twice and reads `document.activeElement` back
(`focused-before=true after=Move Library storage — Fixtures`). Two others are worth naming:
`last-row-unclamped` is caught by the *suite never finishing* — `Number.MAX_SAFE_INTEGER` is how
every caller says "last", and before the clamp `settle`'s pull-up counted down from it one row at a
time, a synchronous loop vitest's own timeout cannot interrupt, which is how three board tests hung
with nothing printed; and `registry-missing-a-kind` is caught by the compiler, which is the
registry's whole point. The harness, the fixture server, the screenshots and the focus check all
live in the worktree's `target/`, which `release-goal.sh` deletes: read them, or copy them out,
before releasing.
