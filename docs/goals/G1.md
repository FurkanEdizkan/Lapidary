# G1 — App-wide event stream

**Status:** open
**Branch:** `feat/events-stream`
**Wave:** 2 · **Kind:** Rust (small) · **Depends on:** W0 · **Migrations:** 0049

## Why

The dashboard updates live, without polling. The only stream today is per ingest batch and closes itself, and one
Postgres listener per browser tab was rejected in `crates/lapidary-api/src/jobs.rs`. This goal gives the app one
stream, backed by one listener per api process. Design: [`phase-6.md`](phase-6.md) § App-wide events.

## Facts checked (as of `3964524`)

- `crates/lapidary-api/src/jobs.rs` `batch_events`: re-reads a batch every second, closes on finish or after 30 min;
  its comment is why a listener per tab was rejected.
- NOTIFY channels today: `lapidary_jobs` (worker wake, `lapidary-db/src/jobs.rs:20`), the sharing channel.
- `AppState` is built in 88 places — so the stream gets its own router, merged in `bin/lapidary-server/src/main.rs`
  (~606, the api role), the way the ingest router is.
- ARCHITECTURE says the web container proxies `/api` and `/events` with `X-Accel-Buffering: no`; the Caddyfile proxies
  `/api/*` only and nothing sets that header.

## Stages

1. `0049`: `lapidary_changed()` → `pg_notify('lapidary_events', library_id::text)` after insert/update/delete on
   `part` (per row) and after `UPDATE OF state` on `job` when the new state is `done` or `failed`.
2. One `PgListener` per api process; the hub groups per library over 250 ms, sends `AppEvent::Changed` on a
   `broadcast`; `Lagged` or a listener reconnect becomes `Resync`; the hub ends on shutdown and so do the streams.
3. `GET /api/events` (`events::router(hub)`, api role), `X-Accel-Buffering: no` and `Cache-Control: no-cache` there
   and on the batch stream.
4. **Tests** (`crates/lapidary-api/tests/events.rs`): one part insert in library A gives `changed{A}` within 1 s; 100
   inserts in one transaction give exactly one event; two subscribers and still one `LISTEN` backend in
   `pg_stat_activity`; the headers; a lagging subscriber gets `resync`; shutdown ends the stream; a job reaching
   `done` notifies.
5. **Measured through containers** (lane port block): `curl -N -H 'Accept-Encoding: gzip' <web>/api/events` shows
   `changed` within 1 s of an upload finishing; five tabs, one LISTEN backend. Docker: this goal may start compose
   projects named `lapidary-lane<n>-*` from the existing `lapidary-check-*` images (tagged per project); no builds.
