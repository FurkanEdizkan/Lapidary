## Audit

Taken 2026-10-18 on lane 2's e2e stack (`stack.sh build/up/seed`, signed in as the rig), headless Chrome through
`scripts/e2e/cdp.mjs`, 1440×900 and 390×844, 49 shots in `/mnt/Storage2/lapidary-a17-shots` (viewport and full page).
The seed has no pictures, so every card and stage shows its no-picture state; that is most parts in a real library
too, so it is the state to design for. Setup could not be seen (the stack is set up; `/setup` shows a dead end, below)
and is audited from `routes/setup.tsx`. Each problem names the goal that fixes it.

**Sign-in (`/login`)**
- A 28rem column floats in an empty 1440px room: the page has no left half, nothing says what Lapidary is. → A19: the
  Doorway split (DESIGN.md § Doorway), lattice left, form right.
- At 390 the standing **Sign in** wraps to two lines beside the forgot-password note. A primary control never wraps.
  → A19: the note goes under the button, full width; the button is `whitespace-nowrap`.
- `Doorway` uses `min-h-screen` (100vh), which jumps under a mobile address bar. → A19: `min-h-dvh`.
- `pt-[12vh]` puts the mark and heading at different heights on every screen. → A19: centre the form block in its half.

**Setup (`/setup`)**
- On an install that is already set up, `/setup` shows "Set up Lapidary" and a bare Sign in link: a heading for a
  page that is not there. → A20: say in one sentence that this install is set up, with Sign in as the standing control.
- One long form with no sense of where you are or how much is left. → A20: the Stepper (DESIGN.md § Stepper).

**Shell (AppFrame, every signed-in page)**
- Four standing controls on the right at 1440 (Library, Import, Upload, account) all carry the same weight, and
  Import and Upload read as one intent twice. → A21: Upload stands; Import and Library are quiet.
- At 390 the header is three rows, about 140px — a sixth of the screen — before a single part. → A21: one 56px row
  (menu, mark, search icon that expands, Upload as an icon, account); Library and Import move to the drawer.
- The places switch marks Parts, Dashboard and Shared with me, but on Settings, People, Profile, Tags and the part page

- No `<meta name="theme-color">`; the drawer and dialogs lack `overscroll-behavior: contain`; nothing sets
  `touch-action: manipulation`. → A21 (theme-color, drawer), A22 (dialogs).

**Dialogs (Import, Share, folder picker)**

- The dialog title is the same size as body text. → A22: Title at 15px/600 (Scope), lead in Ash.
- The native file input ("Choose Files No file chosen") is unstyled and reads as plain text. → A22: a quiet button

  → A22: Add N stands once N > 0; the whole-folder action is quiet.
- At 390 the dialog is a centred box with the page header visible above it. → A22: bottom sheet under `sm`.

**Dashboard**
- Empty dashboard: the "Nothing on this dashboard yet" heading is smaller than the lead above it, and its action
  (Add a widget) is in the header, 1200px away. → A24: the empty state carries its own standing Add a widget.
- "This arrangement is remembered by this browser" is 11px under the lead, a note at caption size. → A24: Graphite
  12px, after the sections.

**Settings**
- The Port field looks like an input you can type into, but it is read-only. → A24: a read-only value is mono text
  on a Bench Grey well with no Edge border; an Edge border means operable (The Operable Edge Rule).
- Save and Check are 34px quiet buttons beside a 34px input; Check reads as disabled. → A24: one height (32px), Save
  stands once the field has changed.

**People**
- A person's row is `rig rig admin you` in four unlabelled sizes, then an empty bordered row. → A24: name in Title,

- The add-a-person form is a two-column grid at 1440 that leaves the password hint under one field.
  → A24: one column, 28rem, the hint under its field.

**Profile**
- The empty Display name field gives no hint of the current name; the disabled Change password looks like a resting

**Tags and Shared with me**

- Nothing on the current app moves badly; the problem is that nothing tells you a place changed. → A21: route enter
  (`Rise`, 180 ms), the places marker (`Indicator`).
- Dialog arrival is a CSS keyframe that ignores where the dialog came from. → A22: Motion presence, still 180 ms.
- `transition-property: transform, translate, opacity` on every element means any Motion element is smeared.
  → A18: `transition-none` on every Motion primitive, as DESIGN.md § Motion says.

### What was taken from the skills, and what was not

Used: redesign-existing-projects' audit order (type, colour, states, layout); web-design-guidelines (Vercel) for the
interaction findings — theme-color, overscroll, touch-action, `…`, CTA wrap, `dvh`, initial focus; design-taste-frontend
for the sign-in split (it is the one marketing-shaped page) and for "motion must be motivated"; high-end-visual-design
for "blur only on sticky things" (the header's scrolled blur) and concentric radii (a 10px card holds 7px controls).

Rejected, because they contradict decided rules:
- **Double-bezel nesting** (high-end-visual-design): breaks The One Step Up Rule; a card is one surface on the ground.
- **Pill CTAs, 2rem radii, `py-24` sections**: break the radius ladder (4/7/10) and the density a tool needs.
- **"No element appears statically", 800 ms blur-up reveals, scroll reveals**: break "authored moments only at the
  front door" and the 280 ms ceiling; a person opens this forty times a day.
- **"No 1px grey borders"**: Edge and Scribe Line are the system; Edge is how a control meets SC 1.4.11.
- **Spring physics on hover, magnetic buttons, perpetual micro-interactions**: hover is a 120 ms transition; nothing loops.
- **Grain and noise overlays, mesh gradients**: the lamp is the one gradient; texture would sit behind every picture.
- **Font swap to Geist / Satoshi**: Archivo and JetBrains Mono stay (self-hosted, Turkish subsets).
- **Dual light/dark mode**: dark only, by rule.
- **The em-dash ban**: a copy-style rule for marketing pages; strings.ts keeps its voice. (The `...` → `…` fix stands.)
- design-taste-frontend's own §13 says it does not cover dense product UI or wizards, so it is used only for the
  Doorway.

## Record

- the pivot banner rewritten, since the pass it promised is this one;

- The Four Lit Places Rule became The One Lit Place Rule; The Marked Part Rule is retired; The Front Door Rule added;
- the header, cards, inputs, buttons and Do's/Don'ts carry the audit's rules: one standing control per region, the
  places marker instead of the tray, a 56px one-row header under `md`, read-only values without an Edge, a dialog's
  first focus never on its close button, `…` not `...`.

`.impeccable/design.json` mirrors it (motion tokens, rules, dos and don'ts, key characteristics, overview);
`.design-sync/conventions.md`'s motion and card lines match. CLAUDE.md § Style names both engines and where each may

### Proposed changes to REDESIGN.md (for the owner; not made here)

1. **The Lattice as a stand-in for a missing picture**, at Scribe Line, static, on cards and stages. Most parts have
   no picture (the whole seed, and most of a real library), so the grid is forty identical dark squares. REDESIGN
   keeps the lattice to sign-in and setup and out of the entry bundle; this would move `lattice()` (pure, small)
   into the grid's chunk, so it needs a bundle measurement against A18's +8 KB budget. DESIGN.md follows REDESIGN
   until the owner decides.
2. **Dialog first focus.** If A22's real-pointer check still shows the close button's ring in a dialog's first
   frame, that is blue at rest; moving first focus to the first field would fix it, but REDESIGN says focus
   handling is unchanged.
3. **Places marker timing.** REDESIGN gives the `layoutId` marker 180 ms with no bounce, and also says springs are
   for layout at `visualDuration 0.28`. The marker is a layout change. DESIGN.md takes the 180 ms reading for the
   marker and keeps the spring for the stepper rail and the Lattice's slide; one sentence from the owner settles it.
4. **The no-picture stage is the common case**, not an edge. A16's crop fix and A23's "hero overlay" are scoped to
   a picture; A23 should name the no-picture stage (lamp, format, View on it) as its main case.
5. **The 390 header** is three rows, about 140px of 844. REDESIGN's shell section specifies 56px but not the
   narrow layout; A21 should own a one-row header under `md`.
