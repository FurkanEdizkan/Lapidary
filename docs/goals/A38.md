## Record

- **Encoded ids:** confirmed before the fix. Mira read Lena's part with `/api/parts/%30…` (200). Any id under
  `libraries`, `parts`, `revisions` or `folders` that is not a plain uuid is now a 404 in `auth::scope`. A test covers
  GET, the file, PUT shares, DELETE and a library page, and fails without the fix.
- **Paths:** browse and add normalize a path (drop `.` and empty segments, refuse `..`) before any check, and store
  the normalized form. `./uploads/bob`, `uploads//bob`, `./imports/bob` and `./_removed` are refused. A scan refuses a
  stored source written with `.` or a doubled `/`.
- **Per person:** a scan of a folder added whole skips other people's `uploads/<name>` and `imports/<name>`. New site
  and bundle imports go to `imports/<owner>/…`. Older imports directly under `imports/<site>/` stay where they are and
  keep their parts, but are not rescanned (they belong to no name).
- **Downloads:** the last chunk is held back until the hash agrees, so a changed file of the same size ends short, not
  whole. Range requests keep the size and time check.
- **Smaller:** blob responses are `private`. Freeing the render cache and `?onDisk=true` are the admin's, and the web
  hides both controls from everyone else. Someone else's library on a dashboard tile, or a folder as a move target,
  reads as one that is not there. A username whose `uploads/`, `imports/` or `_removed/` folder outlived a deleted
  account is refused. Wrong setup codes are serialized at one a second. CLAUDE.md names the admin exception.
Rig 30/30, gate 14/14.
