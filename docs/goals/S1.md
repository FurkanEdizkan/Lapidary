# S1 — One process, two containers

**Status:** open
**Branch:** `chore/one-process`
**Wave:** 6 · **Kind:** Rust + deploy (Docker allowed: build and run this goal's own images) · **Depends on:** — · **Migrations:** —

## Why

The api/worker split existed so the `api` image never linked the OCCT kernel. The kernel is gone (R2), both targets
already build from one runtime stage and differ only by `SERVER_FEATURES=worker`, and the jobs crate itself says
ingest takes about 200 ms. Four containers (db, api, worker, Caddy web) for a hobby library is three too many moving
parts; the owner decided on 2026-10-16 that a minimal install is **the app and Postgres**.

## Facts to check before building

- `bin/lapidary-server/src/main.rs` — the `Role` match (api / worker / peer), `worker_router`, `spawn_worker`,
  `ceiling_of(role)` (pool size per role), which config fields only one role reads.
- `lapidary_api::Role` and everything it gates in `crates/lapidary-api/src/lib.rs`.
- `deploy/compose.yaml`, `deploy/Containerfile` (targets `api`, `worker`), `deploy/web/Caddyfile` (what it does
  besides proxy `/api/*`: headers, compression, caching of hashed assets — keep the ones that matter in axum).
- `xtask/src/deploy.rs` (2,146 lines) and `xtask/src/layers.rs` (625): which checks police the api/worker
  boundary and die with it, and which guard something still true.
- `scripts/e2e/stack.sh` and `check.sh`: the services they name.

## Rules

- `lapidary-api` stays a library that builds a Router. The static files are mounted by `bin/lapidary-server`.
- The SPA fallback serves `index.html` for unknown non-`/api` paths only; an unknown `/api/*` stays a JSON 404.
- Hashed assets get a long immutable cache; `index.html` never does.
- Opening a page still never loads a model file.
- The peer role keeps working until S3 removes it — leave its arm alone.

## Stages

1. **One role for api + worker.** The process serves the API and runs the job loop and reaper. Drop the `worker`
   feature, `SERVER_FEATURES`, and `LAPIDARY_ROLE=api|worker` (an old value is refused with a sentence saying the
   variable is gone).
   **Tests:** the server starts with no role and ingests a dropped file; an old `LAPIDARY_ROLE=worker` is refused.
2. **axum serves `web/dist`.** `tower-http` `ServeDir` + SPA fallback, from a configured directory.
   **Tests:** `/` is the SPA, `/parts/x` is the SPA, `/api/nope` is a JSON 404, an asset has `immutable`.
3. **Deploy.** One Containerfile runtime target with the Vite build copied in; `compose.yaml` is `db` + `app`.
   Delete `deploy/web/`. Prune `xtask` deploy/layers checks to what is still true.
   **Tests:** `cargo xtask check-deploy` green; `scripts/e2e/stack.sh up` brings up exactly two containers.

## Done when

`verify slice` green, the rig runs on two containers, and the Record has the image size and cold build time.
