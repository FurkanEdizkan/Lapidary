# M5 — A model's pictures, as a set

**Status:** open
**Branch:** `feat/picture-sets`
**Wave:** 9 · **Kind:** Rust + web · **Depends on:** M1 · **Migrations:** —

## Why

Owner, 2026-10-17: a model or set has several pictures that represent it — from an import's page or
uploaded by hand. An import brings every picture the page has (to a sensible cap), every part of the set
gets them, and a card can show more than its first.

## Done when

An import attaches all of a page's pictures; a card with several offers the rest without opening the
part; nothing replaces a picture a person chose.

## Record

- **Import.** `link.rs` fetches up to `MAX_PICTURES` (12) of the page's pictures once and attaches each to
  every part of the set through `PgParts::add_page_image`. That call appends after whatever the part has,
  and skips any picture whose `source_url` the part already holds, with the part row locked (`Guard::NewSourceUrl`).
  So nothing a person chose moves or goes, and a re-import adds nothing. A 3MF's own thumbnail still goes only to
  a part with no picture (`adopt_part_image`), and since it is indexed first, it stays first on such a part.
- **Card.** `PartCard.imageCount` comes from a count subquery in `grid_columns!` (indexed by
  `part_image_part_id_position_idx`). A card with more than one picture has arrows and an "n of N" badge.
  The first arrow press fetches `/api/parts/{id}/images` under the part page's own `['part-images', id]`
  key; until then the grid makes no request. The arrows are out of the tab order (the part page shows the set
  to a keyboard), show under a pointer, and are always visible where there is no hover. List rows don't flip.
- **Checks.** `tests/link.rs`: two page pictures in order, a person's upload, then a re-import leaves three
  with the upload last. `Grid.test.tsx`: no fetch until the arrow, then the second picture, and wrapping
  around without a second fetch. Rig: a real import of Printables 482910 gave `imageCount` 2, and a re-import
  still 2. A CDP click on "Next picture" in Chrome showed the second blob, "2 of 2", and did not open the panel.
  `verify slice` 14 gates green.
- **Left.** A picture a person deleted from an imported set comes back if the same page is imported again.
  An import is an explicit ask, so this was left alone.
