# R3 — Production stops, and similarity goes with it

**Status:** ready at 7a8a9a2, gate log target/verify-R3.log
**Branch:** `chore/stop-rendering`
**Wave:** 4 · **Kind:** Rust · **Depends on:** R1 (the viewer must stop needing rungs first), R2 (shared files) · **Migrations:** 0054

## Why

Nothing renders any more, so nothing should be queued, swept or re-queued for rendering. This is the goal
where the pipeline actually stops — and it is the one that goes wrong quietly if it is done by neutering
functions instead of deleting types.

**Delete the enum variants.** Every producer then surfaces as a compile error rather than as a judgement
call about what a function should now return.

Shape similarity goes with it: the profile is computed from the stored L0, and there will be no L0. The
owner's decision is that duplicates are not a feature — **identity is the content hash in the background, and
no real file is ever refused for sharing a name**.

## Facts checked (2026-10-03, `73c4836`) — four mechanisms that fail silently or for ever

1. **`PgParts::revisions_missing(Thumbnail)`** (`repo.rs:3104`) returns every revision for ever once nothing
   fills it, and the worker-start sweep re-queues the whole corpus **every boot**.
2. **`jobs.rs:375-387`'s per-format `produce` ladder** feeds the stale-derivative sweep. Leave L0/L1/L2 in it
   and it re-queues for ever.
3. **`POST /api/parts/{id}/rungs/{level}`** (`api/src/derive.rs:337`) answers `202` with a batch id for work
   that will never land; the viewer polls indefinitely.
4. **`PgShapes::stale_revisions`** inner-joins the L0 derivative, so a part with no L0 is never queued for
   profiling and the sweep reports "nothing stale" — **silent**, for ever.

Also checked:
- **The centre of mass is already safe.** `handler.rs:764` records it on the ingest path from the same
  measurement output, so new parts are covered. Only the historical backfill (`derive.rs:96-150`) dies —
  count the affected rows first and settle them with a one-shot, never by keeping an L0 job to get one float.
- **`Outcome::Rendered` is not dead** — it is the common tail for every derive kind and exports remain.
  `Outcome::Profiled` is.
- **`auto_thumbnail` is three things**: a setting, and the library-existence probe for ingest, the derive
  routes and the likeness routes. Keep the one method, rewrite its body as an existence check, rename it,
  and drop the column.
- `rungs_for_blob` (`repo.rs:2571`) feeds `blob.rs`'s `rebuild()`, which promises "being rebuilt". It must
  only promise that for kinds something still builds.

## Rules

- Migration and binary ship together. A worker on the old binary against the new schema fails every
  `profile_shape` job; the new binary against the old schema leaves pending rows nobody can explain.
- **Do not drop `profiled` from `job_outcome_known`.** Finished history keeps its word; `0047` added the
  value and the board's rule is that later restatements keep every value already in it.

## Stages

1. **The types** — out of `DerivativeKind`: `Thumbnail`, `TessellationL0/L1/L2`, `Structure`, `Entities`,
   `Pmi`, leaving the two exports. Out of `JobPayload`: `ProfileShape`. Out of `Outcome`: `Profiled`. Delete
   `lapidary-core/src/{shape,entity,pmi}.rs`. Then follow the compiler.
2. **The four producers** — the ladder to exports only; `revisions_missing` and its callers
   (`part_thumbnail`, `library_thumbnails`, `LibrarySettings`, `set_auto_thumbnail`) deleted; the rung route
   and `RungReady` deleted, with `?variant=l0|l1|l2` falling through to `unknown_variant` so a stale bookmark
   gets a sentence rather than a 500; `rungs_for_blob` → `exports_for_blob`.
   **The test that is the point of this goal:** run `enqueue_stale_derivatives` **twice** against a seeded
   library and assert the `job` table gains **zero** rows both times. That one assertion covers all four.
3. **Similarity** — delete `lapidary-db/src/{shapes,likeness}.rs`, `lapidary-api/src/likeness.rs`,
   `lapidary-ingest/src/shape.rs`, `lapidary-cad/src/shape.rs`, and their tests.
4. **Migration 0054** — delete pending `profile_shape` and render-kind `derive` rows; `DROP TABLE
   part_link`; `DROP TABLE part_shape`; `ALTER TABLE library DROP COLUMN auto_thumbnail`.
   **Tests:** a pending render job is gone after the migration; a finished one keeps its outcome and its
   batch still totals correctly.

## Done when

`verify slice` green, a worker restarted twice queues nothing, `?variant=l0` answers in words, and
`web/src/bindings` has no orphaned files (ts-rs writes, it does not prune — delete the stale ones by hand).

### The four mechanisms, and how each one is held shut

| Mechanism | What it did | What holds it now |
|---|---|---|
| `jobs.rs`'s per-format `produce` ladder | re-queued every rung and CAD read, at every worker start, for ever | `DerivativeKind::ALL` — the list *is* what something can still build |
| `PgParts::revisions_missing(Thumbnail)` | reported every revision missing a thumbnail for ever | deleted, with `part_thumbnail`, `library_thumbnails`, `LibrarySettings` and `set_auto_thumbnail` |
| `POST /api/parts/{id}/rungs/{level}` | `202` + a batch id for work that would never land; the viewer polled it for ever | route and `RungReady` deleted; `RungReady` → `ExportReady` for the export route |
| `PgShapes::stale_revisions` | inner-joined the L0, so a part without one was **silently** never profiled | deleted with `shapes.rs` and the whole of shape similarity |

**`revisions_missing` is not in the worker-start sweep** — R3.md's fact 1 says so and it is wrong.
`bin/lapidary-server/src/main.rs:407` calls `enqueue_stale_derivatives` and nothing else; the
caller was `POST /api/libraries/{id}/thumbnails`. It went either way.

**The test that is the point of this goal**, and it would have passed on broken code.
`two_worker_starts_over_a_library_of_dead_derivatives_queue_nothing` seeds one library with all
four shapes — a stale `thumbnail`, stale `tessellation_l0/l1/l2`, `structure`, `entities` and
`pmi` rows, a mesh revision with a volume and no centre, and a part with no L0 at all — runs
`enqueue_stale_derivatives` twice and asserts the `job` table gains zero rows both times. It was
red at 8 jobs before the deletions. **Its last leg is a positive control and is not decoration:**
`enqueue_stale_derivatives` logs and swallows every database error, so a sweep whose SQL no longer
parses is exactly as silent as a sweep with nothing to do. A stale *export* must still queue
exactly one rebuild, and `mutate-r3.sh`'s `sweep-finds-nothing-at-all` and `sweep-never-runs` are
the two mutations that prove the control works.

- **Similarity:** `lapidary-db/src/{shapes,likeness}.rs`, `lapidary-api/src/likeness.rs`,
  `lapidary-ingest/src/shape.rs`, `lapidary-cad/src/shape.rs`, `lapidary-core/src/{shape,link,
  entity,pmi,assembly}.rs`, their tests, the dashboard's duplicates tile and `PgParts::purge`'s two
  statements for the dropped tables.
- **`auto_thumbnail` was three things**, as R3.md said. The method survives as
  `PgParts::library_exists` — a `bool`, because there is nothing left to read, only to confirm —

### Migration 0054

Four statements, and one deliberate omission.

1. `DELETE FROM job WHERE state IN ('pending', 'running') AND (kind = 'profile_shape' OR (kind =
   'derive' AND payload->>'produce' IN (…seven render kinds…)))`. **Running, not pending alone:**
   `dequeue` reclaims a running row whose lease expired — that is the whole design of reclamation
   without a sweeper — so one left behind is claimed by the next worker and fails on a payload
   `from_row` cannot parse.
2. `job_outcome_known` is **not** restated. `0047` added `profiled`, finished rows hold it, and
   `job_done_has_outcome` requires a finished job to say how it finished. `batch_status` counts
   outcomes by name and never had a `profiled` column, so such a row still totals correctly.
3. `DROP TABLE part_link; DROP TABLE part_shape;`
4. `ALTER TABLE library DROP COLUMN auto_thumbnail;`

**It does not touch the `derivative` rows.** Every `thumbnail`, `tessellation_*`, `structure`,
`entities` and `pmi` row is still there and still served to anyone holding its hash; that is R4's
`0055`, which needs `recount`'s predicate and the quarantine path, and a migration cannot unlink a
file at all. Every reader of `derivative.kind` filters in SQL or drops what it does not know, so
those rows are invisible to this build rather than an error — checked at `rungs_for_blob`'s
`filter_map`, `batch_status`'s `count(*) FILTER`, `failures`' SQL and `from_row`.

### Two holes the compiler could not see

**`PgJobs::retry` resurrected jobs nothing can run.** `0054` leaves the **failed** dead rows alone
on purpose — deleting them would change the totals of a batch somebody already read — and retry's
only exclusion was `migrate_storage`. Pressing Retry set one pending, the worker refused it, and
the person who pressed it read "this job's payload is malformed" about work that was removed from
the product: CLAUDE.md's error rule, and the "pending rows nobody can explain" `0054`'s own header
warns about. The filter is positive now, off `JobPayload`'s kind constants and
`DerivativeKind::ALL`, so deleting another variant is a compile error there.

**`PgJobs::failures` was checked and is fine:** pure SQL, never parses a payload, so a failed
`profile_shape` row is listed with its own `last_error` rather than 500ing the batch it is in.

### Tests

`cargo test --workspace --all-features` and the web suite are green; the gate log is
`target/verify-R3.log`.

Three rules are held open where the deleted ones were:

- `the_stale_sweep_never_queues_a_kind_nothing_builds` — seven stale rows of six dead kinds, zero
  queued, with a positive control in the same library.
- `only_old_exports_are_cache_and_an_unrebuildable_rung_is_left_alone` — a rung a pre-pivot
  pipeline left is **not** cache, and its blob is neither counted down nor quarantined.
- `a_missing_rung_is_not_promised_a_rebuild_and_queues_nothing` — discriminating, not merely
  absent: the export on the same part still gets the "being rebuilt" sentence.

And `production_stops_and_takes_only_the_jobs_nothing_can_run` applies `0052` by hand, seeds the
whole mixture in one batch — pending, running, done and failed of each kind — and reads the totals
back **through `PgJobs::batch_status` itself**. The first version checked them with a copy of that
query, which would have passed just as happily if the real aggregate were broken.

**Tests that would have passed on broken code, and what changed:**

1. The headline sweep test, without its positive control (above).
2. The migration's totals, against a copy of `batch_status`'s SQL (above).
3. **One that could never have passed.** The first `?variant=l0` assertion was
   `!body.contains("l0")`, and the refusal quotes the requested variant back — so it was
   unsatisfiable, not merely weak. It asserts on the text after `"This server serves"` now, which
   is what the sentence *offers*.

### Mutation check

`target/mutate-r3.sh` (`sweep|binds|routes|cache|migration|all`), logs in `target/mutations-r3/`.

| group | mutations | result |
|---|---|---|

| binds | `sorted-binds-material-and-tag-swapped`, `search-binds-material-and-tag-swapped` | caught — these are R1's warning about renumbered binds, made into a test |
| routes | `refusal-offers-a-rung-again`, `rung-route-back-on-the-router` | caught |

| migration | `migration-spares-a-running-row`, `migration-drops-profiled`, `retry-resurrects-a-dead-job` | caught |

**The deleted fifteenth, `rebuild-promises-a-rung`, is worth more than the fourteen.** It survived, and
the reason is that it was **vacuous**: it ended by rebinding `rebuildable` to `DerivativeKind::ALL`
again, so the mutated code behaved identically. It could not have been written any other way —
`DerivativeKind` has two variants now, both exports, so **there is no rung to put back into the list**.
The rule it was trying to check is held by the type rather than by a test, which is the strongest place
to hold it; a mutation that cannot express the violation is noise rather than evidence, so it is gone
with its reason written where it stood.

### Decided without the owner

1. **`crates/lapidary-cad/tests/calibration.rs` deleted** (454 lines). It is the calibration of
   `NEAR_DUPLICATE_DISTANCE`, a constant this goal removes, and it imported `profile`, `distance`
   and `size_band`. R5.md makes keeping its harness "stripped of profiling" an owner decision and
   this lane took the other option: a dead calibration of a deleted constant is worse than none.
   **It is the only thing that ever measured how many of the owner's 1,095 real files we can
   read** — restore it from `bafabd8` if that number is wanted; a parse-rate loop over the corpus
   index is about twenty lines without it.
2. **`PartDetail.kernelVersion` ("Measured by") removed from the part page.** It read
   `derivative.kernel_version`, and that column lives only on a derivative row. After R4 the only
   non-null answer would be for a part somebody had exported — so the field would quietly become
   "has this part been exported", which is worse than absent. Nothing records which build measured
   a part now; the revision's timestamp against the deploy is what is left.
3. **The part page stops promising a centre-of-mass re-read.** See the decision at the top of the
   hand-back.
4. **`rows_by_id`, `set_topology`, `centreless_revisions` and `CentrelessRevision` deleted** rather
   than left as `pub` reads with no caller. `-D warnings` cannot see an unused `pub` item, and this
   goal's thesis is that a function with no producer is a judgement call waiting to be got wrong.
   The `revision.face_count`/`edge_count` columns and every reader stay: old STEP revisions hold
   them, and a diff that dropped them would lose real data from the page.
5. **One `check-strings` exemption re-keyed.** Its digest keys on the literal's own text and this
   goal edited that SQL, which is the check doing its job.

### Left for later, and for the other R goals

- **For R4.** `cache_kinds` — in R4's file — is now `DerivativeKind::ALL`, and its tests must seed
  the dead kinds in **raw SQL**, as this goal's do: `DerivativeKind` cannot name them. **The

  against every stored export row, so changing it re-queues every export in the corpus at the next

- **`PgParts::set_metadata` has no caller in `src/` any more** — the stage-4 header write was its

  when R6 rewrites the materials paragraph.

  through the OCCT sidecar"; nothing in the product is long enough to need one now.
