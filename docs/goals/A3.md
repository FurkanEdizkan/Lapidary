# A3 — Models per person

**Status:** open
**Branch:** `feat/models-per-person`
**Wave:** 11 · **Kind:** Rust + web · **Depends on:** A2 · **Migrations:** 0065

## Why

Owner, 2026-10-17: a model is visible only to the person who added it unless shared.

## Decisions

Binding: [`ACCOUNTS.md`](ACCOUNTS.md), the plan the owner approved on 2026-10-17. Read the sections this goal names
before writing code.

## Done when

Every read and write of a part, picture, file, blob, event and job is scoped to the signed-in person; a cross-user isolation test covers every route group; site keys are per user.

## Record

- **The guard (`auth::scope`).** It runs inside `require_user`, once per request. It reads the path:
  - `/api/libraries/{id}/…` and `/api/folders/{id}` need the library to be the person's.
  - `/api/parts/{id}…` and `/api/revisions/{id}/…` need the part to be theirs. A4 adds shared, which is read-only:
    GET and HEAD only, otherwise `403`.
  - Somebody else's existing row is refused with the same `no_such_library` / `no_such_part` / `no_such_folder` the crate
    uses for an unknown id.
  - An id that names nothing is left to its handler, so every route keeps its own 404 wording. `ponytail:` a route with
    its own wording can therefore tell "never existed" from "someone else's" by its body; ids are UUIDv7 and unguessable.
- **The rest.**
  - `list_libraries` returns the person's own. `create_library_for` gives the library to its maker.
  - A new part's `owner_id` is its library's owner (`insert_part_chain`).
  - The blob route asks reachability for the viewer (`derivative_is_reachable`, `image_is_reachable` take a `UserId`).
  - The dashboard refuses a tile on somebody else's library ("not there any more"), and leaves an unknown one to the
    widget's own read.
  - `/api/events` streams only the person's libraries, read when the stream opens (`ponytail:` a library made later is
    heard after the next reconnect).
  - The Import browser shows only the person's own folder in `uploads/`, and refuses another's.
- **Migration `0065`.**
  - Owner indexes.
  - Library name and slug are unique per owner, so two people can both have a "Prints".
  - `site_key` is keyed `(user_id, site)`; existing keys go to the first admin. `PgSiteKeys(pool, user)` everywhere, and an
    import or "Fetch details" uses the library owner's key. The page cache is keyed by owner and URL.
  - `profile` is dropped. The wizard no longer pre-fills a name.
- **Owner columns stay nullable.** A row made before setup has none until setup claims it, and the guard treats it as
  nobody's.
- **Tests.**
  - `tests/common` claims what nobody owns, as setup does.
  - `tests/isolation.rs`: a second account with her own session gets `[]` for libraries and `404` for:
    - Lena's library: its parts, facets, folders, sources and tags, and a scan;
    - Lena's part: the part, its file, its images, its tags and deleting it;
    - Lena's picture by hash.
  - It also checks:
    - a picture hash is reachable by its owner only;
    - a dashboard tile on Lena's library fails;
    - Lena's site key is invisible to the other account;
    - the other account may make a library with the same name.
  - Rust: 598 passing. `verify slice`: 14 gates green. Rig: 17 seed checks and 25 flows ok.
