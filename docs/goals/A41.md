# A41 — First-run setup, filled in and driven end to end

**Status:** merged
**Branch:** `feat/setup-whole`
**Wave:** 18 · **Kind:** Rust + web · **Depends on:** A40 · **Migrations:** —

## Why

Owner, 2026-10-21: a setup process for a first installation that makes the admin and configures the system, with
the steps sliding left and right. The wizard exists (A1, A5, A6, A20), but no browser flow drives it, its slide is
16px against DESIGN.md's 8px, the import-links choice can't be changed after setup, the sign-in pictures are not
offered, and how many imports run at once is an environment variable only. The owner chose to fill those gaps, and to
let an admin choose the import count.

## Done when

- An instance setting `import_workers` (1–8, default 2): chosen in the wizard's Options step and in Settings › Server,
  locked when `LAPIDARY_WORKER_CONCURRENCY` fixes it, applied by a restart. The worker default drops from 4 to 2 to
  match the 2 CPUs.
- The wizard's Options step also offers the sign-in page pictures.
- Settings offers the import-links switch to an admin.
- `Step` slides 8px each way.
- A rig flow `setup` drives the real wizard on a fresh stack, before `seed`.
- Gate and rig pass.

## Record

- **Import workers, a saved setting.** `import_workers` (1–8) in `instance_setting`, read when the worker starts
  (`bin/lapidary-server/src/workers.rs`): `LAPIDARY_WORKER_CONCURRENCY` when set, and then locked, else the saved
  number, else the default, which drops from 4 to **2** to match the 2 CPUs. compose passes the variable through
  empty now; it wrote `:-4`, which would have fixed it on every install. A change from Settings saves and restarts
  through the models folder's restart token. Resizing the running worker is skipped: its drain takes every permit.
- **Setup carries the count** (`SetupRequest.importWorkers`, refused out of range before any account is made), so
  Finish restarts once: through the folder change when there is one, else through `PUT /api/settings/workers`. The
  sign-in pictures, on unless turned off, are saved after the account exists through the existing wall route.
- **The import switch in Settings:** `PUT /api/settings/sites`, admin only, refused when
  `LAPIDARY_IMPORT_LINKS=false` decides it; the list says `forcedOff`.
- **Slide:** 8px each way, as DESIGN.md § Stepper said; the code had drifted to 16 in 6c69dfd.
- **Two older bugs the rig found:** `followRestart`/`followPort` kept the page's path, so a setup that moved the
  port or restarted came back to `/setup` and its "Lapidary is set up"; they take a path and the wizard passes `/`.
  And `followRestart` looked every 250ms for the server going down, while a restart came back in half a second, so
  it missed the gap and waited out 15s; it looks every 50ms.
- **Rig:** `scripts/e2e/setup.mjs` runs from `sign_in_rig` on a fresh stack: the intro's Skip, Back keeping what
  was typed, a wrong code sent back to step 1, the sign-in pictures on, the count from 2 to 3, Finish, the restart
  followed to `/` signed in, and `/api/settings/workers` reading 3 (the log: `concurrency=3`). Then 30/30 flows.
  In Settings on the same stack: the count saved back to 2, the page back in 669ms, the log `concurrency=2`.
- **Also:** `rustls-webpki` 0.103.16 for RUSTSEC-2026-0382, which failed `cargo deny` on main the same day.
- **Disk:** `/` had 4 GB free; the owner said to clear space, and only the unused build cache was pruned
  (5.7 GB, twice — the build makes it again). No image, container or volume was removed.
- **Gate:** 14/14.
