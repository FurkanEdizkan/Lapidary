## Record

### Stage 1 — three installations, and no image built (done)

**Nothing was built.** `git diff --name-only 93b87eb..HEAD` is `docs/` and `scripts/e2e/` only, so the five
`lapidary-e2e-4-*` images T1 built **are current `main`'s application, byte for byte** — the api, worker, peer, db and
web of this tree. The three installations borrow them under their own project names (`docker tag`, no layer, no pull,
no prune), and the *after* captures are taken against a bundle built with `npm --prefix web run build` and copied into
the three web containers with `docker cp` — Caddy serves `/srv`, so a web change is on screen without an image and
without the compile lock. **Anybody reading these captures should read them as T1's images at `93b87eb` plus this
branch's bundle, not as proof that an image was rebuilt.**

The rig grew a suffix rather than a fourth throwaway harness (lead's call, and the reason T1 exists):

- `AS=a|b|c` suffixes the compose project, the work directory and the images, and shifts the lane's four ports by 100
  per letter: **34000/34080/34081/34082, 34100/…, 34200/…**, all inside lane 4's own block. Both refusals, the resolved
  port verification, the reverse chown and the "nothing is owned by another user" assertion apply to each of the three
  unchanged.
- The project pattern is now exactly `^lapidary-e2e-[0-4][abc]?$`, and because that widening would have let
  `LAPIDARY_LANE=4a` through, the **lane itself is asserted separately** as one digit. `check.sh` went from 69 to **83
  assertions**: `AS` of `d`, `aa`, `A`, `1`, `ab` and a lane spelled `4a` are each refused with no docker call, and a,
  b and c are each accepted on their own three ports — without those last three the refusals would prove nothing.
- `up --min-ram <gib>` **says out loud in the log** that the 5 GiB default was gone under, rather than lowering the
  default. These runs used **3 GiB**, agreed with the lead: the default's premise is one stack whose declared ceilings
  total 4.3 GB, and three installations that are never seeded are a different case. Available RAM was 5–8 GiB
  throughout and nothing was killed.
- `peer stop|start` takes an installation away through compose, so the relay case is made by stopping a process rather
  than by naming a container by hand.
- `group.sh` is goal 9's `run-group.sh` moved onto the rig: three installations, the whole scenario through their three
  apis, and a capture at each point where a screen exists. `group.sh dist` and `--dist` serve a freshly built bundle;
  `group.sh down` tears all three down.
- `sharing-shots.mjs` drives the screens through `cdp.mjs` — no second transport.

**Measured, from nothing, every run:** three installations **healthy in 6–7 s each**, A's five-part ingest tree scanned
in 2 s, the whole scenario with 24 captures in **1 min 41 s**, and teardown leaving no `lapidary-e2e-4[abc]` container,
volume or image tag, nothing root-owned, and **the owner's two `lapidary_lapidary-*` volumes present and untouched
after every one of the four runs**.

**The ingest tree is deliberately not `example/parts`.** Every installation's worker seeds those six into its own
default library on first start, so a folder made of them arrives at the other two **already held** — every card reads
*In your library* and there is nothing left to press Pull on. One example part is kept for exactly the opposite reason:
it is the card that honestly says the file is already here. That was found by running it, not by reading.

**Three more things the first run taught the scenario**, each of which had made a screen photograph a lie: a share
reaches the other installation on the next hello round, so a pull started before it arrives is a pull of nothing and
the requests screen photographs its empty state; `value[0]` is not Terrain once two folders are offered, so a count
asserted against the wrong folder waits three minutes and then lies; and confirming the share dialog on the first width
leaves every later width photographing a different screen (a folder already shared has no picker).

**A rig bug that predates this goal, fixed here:** `up` printed `--compare: command not found` on every run since T1 —
an unquoted heredoc was expanding a backticked word inside a python comment. Harmless, and it reads exactly like a
failure.

**`shot` takes `{ full }` now.** The first set of captures was the viewport, and the sharing page is three screens tall
at 390: everything below the fold was missing, which is a poor way to find out that a list nobody could see reads badly.

### Stage 2 — what looking at them found

**The impeccable detector is clean on all three files — zero findings.** Worth saying, because it means everything
below is judgement rather than lint, and no amount of static checking would have produced it.

The `impeccable-finish-reviewer` ran over the 22 before-captures. **Fixed, all inside this goal's files:**

1. **A peer card said "No folder in common any more" directly above a link to that peer's folder.** `foldersInCommon`
   counts the folders this installation offers them plus the rosters it is named on, and **never the owner of a folder
   it holds** — so the person whose folder you are reading is told you have nothing in common. The two lines were
   written by different components and could contradict each other; there is one slot with one answer now, and what
   they share wins. The db side is left for later, below.
2. **Three strings promised "everyone you are paired with" beside a picker that chooses who it goes to** — `shareBody`,
   `askFirstNote` and `stopNote`. The first now counts what is offered and lets the picker say who to; the other two
   say "everyone it goes to".
3. **The "Asking to pull" section stood on installations with no folder that asks first**, saying nobody had asked for
   something that cannot happen. A folder is open unless somebody says otherwise, so that is most installations. It
   appears when there is a share that asks first, or somebody asking — the rule `Introductions` already follows.
4. **The members dialog named no folder** although the page lists several. It is *Who Terrain goes to* now.
5. **A card's "Download" does not download.** It pulls the part into your library, and the five lines around it say
   pull — "Pull into", "Pull all", "Pulled 1 file", "Parts you already pulled are not fetched again". In an
   application whose rules make Download a load-bearing word (`variant=original` returns byte-identical bytes), the
   same word for two different things is the one control here nobody could predict. It says **Pull**.
6. **The pull status line was set in the mono face.** `.tabular` is mono plus tabular figures and `styles.css` keeps it
   for "a part number and a dimension … rather than as prose"; this line is a sentence. `tabular-nums` keeps the digits
   from jittering while a pull counts up, without the face.
7. **At 390, two rows of one list wrapped into two different shapes**, because a single `flex-wrap` decided one button
   at a time. The actions are a group that takes its own full-width line; the request row's standing and the
   introduction row's address take theirs. **A peer's port was broken across lines** by `break-all` on one string
   holding the device id and the address — a port is the thing a person retypes, so they are separate lines, and the
   two pickers truncate a long address instead of pushing the dialog wider than the phone.
8. **The share dialog was enabled before the people arrived.** Share unlocked on the licence count, so a fast hand
   confirmed with no member list at all — which reaches everyone paired, whatever the picker showed. It also says
   `membersNone` when nobody is ticked, as the members dialog already did.
9. **The relayed line was the quietest thing on the screen it matters most on.** "As Burak's bench read it, …" sat in
   the same 11px muted slot as "Last read …". It is `text-sm` in the relayed branch.
10. Singular counts dropped the word the plural carries: "Terrain, 1 part" against "Terrain, 3 parts offered", and the
    same in `librarySharedBy`.

**Returned by the reviewer and deliberately not done** — with the reason, because a review is not a mandate:

- *Rename the already-shared share dialog ("How Fasteners is shared", body and button to match), and link the sharing
  page it names.* The dialog is still sharing, and with the switch now on the sharing page it is no longer the only way
  to change the mode; "Shared libraries" is in the top nav of every page, one click away, so the instruction is not a
  dead end. Left as a copy decision for the owner.
- *A sentence on the relayed page saying the owner is unreachable and this list is second-hand.* "As Burak's bench read
  it" already says it; it is now said at `text-sm`. A second sentence is copy the owner should choose.
- *A note under the seeding switch when it is on.* Its label already says the consequence — "Serve this folder's files
  to the people in it" — and the count says how much of it is possible.
- *"2 parts have no licence recorded" should say the consequence.* True, but the neighbouring non-commercial line
  already carries that sentence, so the fix is to say it once for both, which is a rewrite of the licence warning
  rather than a finding about these screens.
- *Split "Nothing shared with you yet" for somebody who shared and stopped.* With fix 1 in place that line only shows

- *Move the recipients line above the row's actions.* The order is the same at 1440, where it read fine, so this is an

### Stage 3 — the two owner-side gaps (done)

**The gap was not in the api.** `POST /api/libraries/{id}/shares` has taken `asksFirst` on an existing share since goal
9. `shareCategory` sent the field **only when it was true** (`...(asksFirst ? { asksFirst } : {})`), and the api reads
absent as *keep what it had* — so switching a share back to open was unreachable from every page in the application, api
or no api. The helper says it when it is given one.

- **Each share's row carries the switch.** `GET /api/shares` says what is shared and not which library's category each
  one is, so the page joins through the libraries' own shares read — one query, under the key each library's tree
  already uses, so a page that has been to a library pays nothing for it. A row whose category is not known yet shows
  where the folder stands and cannot be switched blind.
- **The badge went.** "Asks first" beside the part count and a switch saying the same thing two lines below is one
  state in two places.
- **The regression the fix would have introduced, caught before it shipped:** once `false` can be sent, the share
  dialog's box — which always started unticked — would have turned an ask-first folder open on a re-share nobody meant
  as a change. It starts where the folder stands, read from the library's shares.
- **`PgShares::requests` filters `s.mode = 'ask'`.** A share that no longer asks first has nothing to decide: everybody
  it reaches may pull it, so granting an old ask changes nothing and denying one stops nobody. **The rows are not
  deleted** — switching back to asking first brings every ask back with what was answered, which the db test asserts in
  both directions.

**Driven end to end, not only tested:** the switch on A's page turned Fasteners from asking first to open and back
again, and the api agreed within a second each way (`a-ask-first-off@1440.png`, `a-ask-first-on@1440.png`). The stale
request is still listed in that shot, and correctly so: those images predate this branch's db read, and the drop is what
the db test proves.

**Mutation-checked, four rules, each broken on purpose and restored:** the mode filter removed from `requests` fails
the db test on *"a share that no longer asks first has nothing to decide"*; the helper dropping a false `asksFirst`
fails both "switches back to open" tests; the row writing the taken-back line again fails *"somebody whose folder this
installation holds is never told there is nothing in common"*; and the asking-to-pull section left unconditional fails
its own test.
