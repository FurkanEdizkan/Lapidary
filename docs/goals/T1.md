# T1 — The whole app, up and driven

**Status:** open
**Branch:** `test/e2e-rig`
**Wave:** 1 · **Kind:** tooling (Docker builds allowed for this goal) · **Depends on:** B0 · **Migrations:** —

## Why

Three harnesses have driven this application — `target/docker-check/check-plain.sh` (goal 8),
`target/docker-check/group/run-group.sh` (goal 9), `target/ui-verify/verify.mjs` (the UI refinement) — and all three
were scratch: each goal wrote one and threw it away. The board already asks for a fourth (W3: "both Phase 6 exits
measured on the merged `main` through a compose stack on a lane port block") and the backlog asks for a fifth (the
1,000-part UI sweep). This is that tool, committed once, so W3, G5, G6, L1 and every later goal run it instead of
writing it again.

It is also the first end-to-end test this repository has had. The 31 web test files (~330 tests) all run in jsdom with
`fetch` stubbed; nothing has ever asserted that the real api, the real worker and the real browser agree.

## Facts checked (2026-09-26, `5e7a4cd`)

- `deploy/compose.yaml` declares `name: lapidary`, and the owner's `lapidary_lapidary-db` and `lapidary_lapidary-uploads`
  volumes **exist on this machine right now**. A compose call without `-p` would target them. Host ports are literals
  (web `3000:8080`, api `8080:8080`, worker `8081:8081`, peer `8082:8082`); there is no port variable.
- `cargo xtask check-deploy` reads only `deploy/compose.yaml`, `deploy/compose.sharing.yaml`, `deploy/Containerfile`
  and `.github/workflows/containers.yml`; `check-strings` scans `.rs` under `crates/`, `xtask/`, `bin/`. **Nothing in
  `verify slice` lints a shell or `.mjs` file** — this rig polices itself or nothing does.
- `scripts/claim-goal.sh` writes `LAPIDARY_PORT_WEB/API/WORKER/PEER` (`3n000/3n080/3n081/3n082`) into each lane's
  `.lane.env` and **nothing in the repository reads them**. The main checkout's `.lane.env` (lane 0) has none.
- `POST /api/libraries/{id}/scan` (`crates/lapidary-api/src/scan.rs:40`) takes a library and **no subpath**: one scan
  is the whole ingest directory into one library.
- `PgBlobs::library_holds` (`crates/lapidary-db/src/repo.rs:872`) joins on `source_path` **and** hash, so the same
  bytes under a new name in one library are a **second part**, not `Skipped` — which is how the identical-duplicate
  case is made, with `cp`. New bytes at an existing path are `Unkept` in a hobby library and a revision in a
  controlled one (`crates/lapidary-ingest/src/handler.rs:538-570`).
- `deploy/Containerfile` has no cargo cache mount. Measured 2026-09-18 (`target/docker-check/build-summary.txt`):
  db 3 s, web 9 s, api 119 s, peer 4 s, worker 125 s, with the OCCT stage already cached. The builder cache is 23.92 GB
  with 8.3 GB reclaimable; `docker builder prune` drops the OCCT layer and costs a 30–40 minute rebuild, so this goal
  never prunes.
- `target/sharing-check/corpus-1000/` is **1,000 symlinks** into `/mnt/Storage2/All/STL Files`, not files; a container
  cannot follow them. `corpus-1000.tsv` is `size<TAB>path`, relative to the corpus root, with spaces and parentheses in
  the paths.
- `example/parts/generate.py` guards `main`, so `rotate_x90(tris)` and `write_stl(path, tris, header)` can be imported.
- `PAGE_SIZES = [50, 100, 250, 500]`, default 50 (`web/src/lib/preferences.ts:18`). The six example parts seed
  `01931b6e-0000-7000-8000-000000000001` (`web/src/lib/api.ts:104`). Caddy proxies `/api/*` to `api:8080`, so a browser
  needs only the web port.
- The machine: `/` 15 GB free, `/mnt/Storage` 159 GB, **about 4 GiB of RAM available**. The compose ceilings total
  4.3 GB, so this stack and a cargo build do not coexist — see Rules.

## Rules

- **Owns** `scripts/e2e/**` (new) and this file. Nothing else. `scripts/` was B0's; the lead grants this subtree.
- **The owner allowed Docker image builds for this goal** (`PROTOCOL.md` forbids them otherwise). Never
  `docker builder prune`, `docker volume prune`, `docker system prune`, and never remove an image not named
  `lapidary-e2e-*`.
- **One compose function with `-p` hard-coded**, used by every call. No bare `docker compose -f deploy/compose.yaml`
  anywhere in the rig: that is the owner's project.
- The override file carries **`ports: !override` and `extra_hosts` only** — never `build:`, `target:`,
  `SERVER_FEATURES` or `LAPIDARY_ROLE`, because `check-deploy` cannot see this file and a role or kernel mistake in it
  would be invisible to the gate.
- **Ask the lead before `build` or `up`.** Only ~4 GiB of RAM is available and two Rust lanes are compiling in this
  wave; the lead says when the machine is free. Everything heavy goes through `cargo xtask heavy -- …`.
- Every output goes under `target/e2e/` — a full `/` loses all tool output.

## Stages

0. **The rig, and its two refusals.** Committed: `scripts/e2e/stack.sh` (`build | up | seed | drive | down | status`),
   `scripts/e2e/e2e.override.yaml`, `scripts/e2e/cdp.mjs`, `scripts/e2e/flows.mjs`, `scripts/e2e/skew-stl.py`. Per-run
   scratch: `target/e2e/<lane>/{e2e.env,ingest/,store/,runs/<stamp>/{run.log,report.json,shots/}}`. `stack.sh` reads
   `.lane.env` — B0's dangling wire — and **refuses** when (a) `LAPIDARY_PORT_*` is unset or names 3000/8080/8081/8082,
   or (b) the project name does not match `^lapidary-e2e-[0-4]$`, checked before anything and again immediately before
   every `down`. Lane 0's block is `30000/30080/30081/30082`, appended by hand to the main checkout's untracked
   `.lane.env` (per-machine, not a repo change).
   **Tests:** `bash -n`, `node --check`; both refusals fire with no docker call (a `set -x` transcript proves it);
   `grep -E 'target:|SERVER_FEATURES|LAPIDARY_ROLE' scripts/e2e/e2e.override.yaml` finds nothing.
   **Exit:** the files exist, both refusals fire, and the gate is green (it says nothing about these files — recorded,
   not assumed).

1. **Build from current `main`.** `cargo xtask heavy -- scripts/e2e/stack.sh build`, one service at a time, each behind
   `/` ≥ 8 GB and `/mnt/Storage` ≥ 20 GB, recording wall time and image size. Under the guard it **stops and asks the
   owner**; it never prunes. Images are `lapidary-e2e-0-*`, derived from the project name, so no two lanes can run each
   other's branch.
   **Tests:** `compose config` prints this lane's four ports and no others; the api image has no OCCT and the worker's
   `occt-bridge version` answers.
   **Exit:** five images and the build summary in the log, `/` still ≥ 8 GB. ~6 minutes warm.

2. **Up, healthy, down, twice.** `e2e.env` holds the credentials, an absolute `LAPIDARY_STORAGE_ROOT` and
   `LAPIDARY_INGEST_DIR` under `target/e2e/<lane>/`, and the four ports compose interpolates into the override. The
   password is generated **only when the file is absent** — `POSTGRES_PASSWORD` is applied at volume init, so
   regenerating it against a kept volume breaks authentication. Order: guard `/` ≥ 6 GB and **available RAM ≥ 5 GiB** →
   make the directories → chown the store to 10001 through a throwaway container → `up -d --no-build` → wait for both
   `/api/healthz`, the web root, and `/api/sharing/identity` naming a device. **`down` reverses the chown first**,
   then `down -v --remove-orphans`, then removes the store: otherwise the store is undeletable by the host user and
   `release-goal.sh` cannot remove the worktree (`target/docker-check/group/a/store` is still root-owned proof).
   `--keep` skips teardown for stage 5.
   **Tests:** healthy in one wait loop; `psql` reports the extensions and the newest migration; after `down`, both
   `lapidary_*` volumes still exist, no `lapidary-e2e-*` does, and `target/e2e/<lane>` is empty and removable.
   **Exit:** up → healthy → down → up again, twice, nothing left behind. ~90 s each way.

3. **A library worth testing.** One ingest tree whose subdirectories become categories: `step/` (the 6 B-rep fixtures,
   through the OCCT worker), `misc/` (the `.obj` and `.3mf` fixtures, for the format facet), `<creator>/<set>/…` (the
   corpus slice, its real paths kept two or three levels deep), `alike/` (the deliberate duplicates). The slice is the
   **smallest 400** rows of `corpus-1000.tsv` read with `IFS=$'\t'` and copied with `cp -L --parents` (the corpus is
   symlinks; `-L` is what makes them files) — about 200 MB. **400 is the number:** 8 pages at the default 50, 2 pages
   at the 250 option, five formats with counts in the hundreds and the tens, and 400 is where a grid stops being a
   demo. The three deliberate duplicates: **identical** (`cp` of the flange under a new name — a second path with the
   same bytes is a second part), **near-duplicate** (`skew-stl.py --rotate`, importing `rotate_x90` and `write_stl`
   from `example/parts/generate.py`, which is exactly the invariance `phase-6.md` claims), **similar but not near**
   (`--scale 1.15`, outside the `ln(1.02)` band by design). Libraries: **Sweep** (hobby) scanned; the **default**
   library left with its six example parts so `web/scripts/open-timing.mjs` still runs against what the Phase 3 exit
   timed; **Governed** (controlled) filled through the chunked upload loop lifted from `check-plain.sh`, then one part
   re-uploaded to reach a second revision — the only way to a history, a diff and a lock, since a scan has no subpath
   and a hobby library answers `Unkept`; **Empty**, created and never scanned, for the empty states.
   **Tests:** `ingested` ≥ 409 and no failures for Sweep; thumbnails = parts; formats present are
   `stl, step, igs, obj, 3mf`; ≥ 8 folders; Governed shows two revisions on one part; a re-scan settles all-`skipped`;
   the PMI cylinder's detail carries `structure`, `entities`, `pmi` and a kernel version (`check-plain.sh`'s
   assertions, kept).
   **Exit:** four libraries and those counts in `report.json`. ~12 minutes, the STEP files dominating.

4. **The driver: one CDP module, flows as data.** `cdp.mjs` takes its **transport from `web/scripts/open-timing.mjs`**
   — that `send` rejects on `message.error`, that `evaluate` throws on `exceptionDetails`, its CDP port is random and
   its profile is removed on close. `verify.mjs`'s transport is the wrong half to copy: its `evaluate` returns
   `undefined` on an exception (so an assertion would pass silently), its port is a fixed 9400 (two lanes collide) and
   it leaks profiles. Lifted from `verify.mjs` unchanged: `shot`, `go`, `mouse`, `click`, `key`, `rect`, the device
   metrics override, `setEmulatedMedia` for reduced motion, the **`matchMedia('(hover: hover)')` shim** (headless
   reports a screen that cannot hover, and much of the grid hangs off that query), the 50-hover `HeapProfiler` check
   and the measurement retry loop. Timing is not reimplemented: the driver shells out to `open-timing.mjs` with an
   explicit `--url` (its default is the owner's `localhost:3000`) and keeps its stdout. A flow is
   `{ name, route, widths, pending?, run(page) → assertion }`; the harness runs each, screenshots either way, and
   appends a row. In priority order: `grid-loads`, `thumbnails`, `search`, `facet-format`, `folder-tree`, `sort`,
   `page-size`, `paging`, `saved-filter`, `selection-bulk`, `quick-look`, `part-detail`, `measure`,
   `section-explode-pmi`, `remove-restore`, `upload` (through the real control, with `DOM.setFileInputFiles`),
   `scan-progress`, `storage-panel`, `sharing`, and `duplicates` marked **pending until G6**. Each at 1440×900; the
   grid, quick look, part detail, removed and sharing also at 390×844; one reduced-motion session repeating the grid
   and the part page.
   **Tests:** the list green against the seeded stack; rename one selector on purpose and that flow alone reports
   `failed`, with its shot, and the process exits non-zero.
   **Exit:** `report.json` with every flow `ok` bar the pending one, about 26 shots, and the timing stdout. ~5 minutes.

5. **The interactive pass** (computer use), for what headless cannot judge: the viewer on the real GPU (spin, LOD swap,
   a 400-card grid scrolled fast), whether the motion feels mechanical, pointer drag on the section plane and the
   explode slider, colour and contrast, and the shots' visual taste. One local Chrome on `DISPLAY=:1` at
   `http://127.0.0.1:<lane web port>` — **never 3000**, which would rewrite the owner's own grid preferences; clear
   that origin's storage first, or a previous run's layout reads as a finding. Hazards, each of which cost a session
   before: extension screenshots hang (shoot with the headless rig); a hidden tab drops key presses and never fires
   `IntersectionObserver`, so lazy thumbnails and the stage's Space key look broken (keep the tab focused, one at a
   time); the extension's network log misreports some statuses, so a 4xx/5xx claim is checked against the api's log or
   `curl`, never quoted from it.
   **Exit:** the findings in the Record, each marked *inside T1* or *for the lead to file*.

6. **Outputs, pass, and findings.** A run writes `run.log` (the whole transcript), `report.json`
   (`{stack, seed, flows, timing}`) and `shots/`. It **passes** when every non-pending flow is `ok`, the seed counts
   match, and teardown leaves no `lapidary-e2e-*` project, no orphan image and no root-owned directory.
   `stack.sh drive --compare <previous report.json>` prints flow-status and timing deltas — the regression signal W3
   needs. A lane cannot edit the board, so findings land in this file's Record, one line each, for the lead to file;
   the worktree dies at `release-goal.sh` and takes `target/e2e/` with it, so the Record quotes numbers, not paths.
   **Exit:** two consecutive runs on one sha with identical flow statuses (flakiness is a finding, not noise).

## Done when

`scripts/e2e/` is committed, two clean runs are recorded, the Phase 6 exits are measurable through it, `verify slice` is
green, and the goal is handed to the lead.
