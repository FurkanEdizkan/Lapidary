# A8 — One-command install, and Lapidary's own files chosen in the wizard

**Status:** open
**Branch:** `feat/install-and-store`
**Wave:** 12 · **Kind:** deploy + Rust + web · **Depends on:** A7 · **Migrations:** —

## Why

Owner, 2026-10-17: a person the project is shared with should get from a clone to the wizard without editing a file,
and the wizard's "Lapidary's own files" should be choosable like the models folder.

## Decisions

- `./install.sh` at the repository root: Podman or Docker, whichever is there; writes `deploy/.env` only when there
  is none (a random database password, and on macOS or Windows the home folder as the browse root, because `/`
  there is Docker's VM); builds and starts; prints the URL and the setup code. An existing `deploy/.env` is never
  overwritten.
- The store is `instance_setting.store_dir`, a host path, chosen in the wizard and saved by the same
  `PUT /api/settings/storage` (`{"store": …}`). `LAPIDARY_STORAGE_ROOT` set in `deploy/.env` fixes it. The current
  store is copied to the new folder first, every file with its modified time and never over a different one, and
  nothing is removed. It can't be inside the models folder or hold it. Settings shows it; the wizard offers it.
- No Docker socket in any container.

## Done when

`./install.sh` on a fresh clone prints a working URL and code; the wizard chooses both folders and Lapidary restarts
on them with every download working; the gate and the rig pass.
