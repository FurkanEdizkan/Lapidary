# A8 — One-command install, and Lapidary's own files chosen in the wizard

**Status:** open
**Branch:** `feat/install-and-store`
**Wave:** 12 · **Kind:** deploy + Rust + web · **Depends on:** A7 · **Migrations:** —

## Why

Owner, 2026-10-17: a person the project is shared with should get from a clone to the wizard without editing a file,
and the wizard's "Lapidary's own files" should be choosable like the models folder.

## Decisions

- `./install.sh` at the repository root: Podman or Docker, whichever is there; writes `deploy/.env` only when there
  is none (a random database password, and on macOS or Windows the home folder as the browse root, because `/`
  there is Docker's VM); builds and starts; prints the URL and the setup code. An existing `deploy/.env` is never
  overwritten.
- The store is `instance_setting.store_dir`, a host path, chosen in the wizard and saved by the same
  `PUT /api/settings/storage` (`{"store": …}`). `LAPIDARY_STORAGE_ROOT` set in `deploy/.env` fixes it. The current
  store is copied to the new folder first, every file with its modified time and never over a different one, and
  nothing is removed. It can't be inside the models folder or hold it. Settings shows it; the wizard offers it.
- No Docker socket in any container.

## Done when

`./install.sh` on a fresh clone prints a working URL and code; the wizard chooses both folders and Lapidary restarts
on them with every download working; the gate and the rig pass.

## Record

- `install.sh`: Podman or Docker compose; `deploy/.env` from `.env.example` with a 32-character password, `chmod 600`,
  and `LAPIDARY_BROWSE_ROOT=$HOME` on macOS or Windows; `up -d --build`; the address and setup code read from the log.
  A second run keeps `deploy/.env`.
- `models_dir.rs`: `Which::{Models, Store}` and one `first()` for both; `store_dir` in `instance_setting`;
  `PUT /api/settings/storage` takes `path`, `store` or both and restarts once. The store is copied whole
  (`copy_tree`: every file, times kept, never over a different one, links left out) and refused inside the models
  folder or around it. `LAPIDARY_STORAGE_ROOT` now fixes it (compose passes it empty unless set).
- Web: the wizard's server step has a second picker for Lapidary's own files; Settings shows it.
- Five web files A6 had run through a formatter with the wrong settings are back to their hand formatting, with only
  A6's edits on top.
- Checks: a store copy unit test. Live, `install.sh` on a fresh clone as its own compose project on lane 1's ports:
  the password and code, both folders chosen at once, the store refused inside the models folder, the restart onto
  both, the examples copied and still downloading, files owned by the installer, a second run keeping the settings.
  Rig: seed 17 ok, flows 25 ok. `verify slice`: 14 gates green.
- **Left.** `install.sh` is untested on macOS and Windows (Git Bash's `$HOME` is `/c/Users/…`, which Docker Desktop is
  expected to accept). The store copy runs inside the request; a large store makes the wizard wait.
