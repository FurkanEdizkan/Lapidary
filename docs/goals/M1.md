# M1 — What the owner saw first

**Status:** ready, gate log target/verify-M1.log
**Branch:** `fix/first-look`
**Wave:** 8 · **Kind:** web · **Depends on:** — · **Migrations:** —

## Why

The owner's first look at the running install (2026-10-17): a picture added on a part's page does not
appear on its grid card until a reload; on the part page the Pictures block is drawn over the File block;
the Lapidary mark in the header does not take you home.

## Done when

Adding, keeping (snapshot) or reframing a picture updates the grid card without a reload; the part page's
sections do not overlap at any width; the mark links to the grid. Each with a test.

## Record

**Done.**
- **The card kept no picture.** Adding a picture, keeping the viewer's view, or reframing one invalidated the
  part's gallery and never `['parts']`, so every grid page kept its old answer until a reload. One helper,
  `picturesChanged`, now refreshes both at all three places. A test watches the invalidations.
- **The overlap was the sticky stage, not the picture.** On a wide screen the stage and its pictures are
  `sticky`, and a sticky box travels to the end of its containing block — which was the whole page grid,
  File and Identity included. Scrolled, the stage slid over them: the owner's screenshot. The studio is now
  its own grid, closed before the sections under it; a scrolled screenshot through the DevTools protocol
  shows the stage stopping above File.
- **The mark goes home**: a router link to the grid, and a plain `<a href="/">` on the crash page, which
  cannot trust the router.
