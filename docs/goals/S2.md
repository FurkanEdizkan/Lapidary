# S2 — Empty crates and pgvector

**Status:** ready, gate log target/verify-S2.log
**Branch:** `chore/drop-placeholders`
**Wave:** 6 · **Kind:** Rust (small) + deploy · **Depends on:** — · **Migrations:** —

## Why

`lapidary-build`, `lapidary-index` and `lapidary-enterprise` are 20-line placeholders for phases that are no longer
planned; `lapidary-api` still depends on two of them. `deploy/db/Containerfile` installs pgvector, which migration
0047 already says nothing uses.

## Facts to check before building

- Every `Cargo.toml` naming the three crates; `xtask/src/layers.rs` rules naming them.
- `deploy/db/Containerfile`: what else it adds besides pgvector (pg_trgm is in contrib, no build needed). If nothing,
  compose uses the pinned `postgres:18` digest directly and the file goes.
- Any migration that `CREATE EXTENSION vector`.

## Rules

- No migration edits. If an old migration creates the extension, a fresh database must still migrate without the
  package — say what you found in the Record and ask the lead before changing anything.

## Stages

1. Delete the three crates and their references. **Tests:** `verify slice` green.
2. pgvector out of the db image. **Tests:** a fresh database migrates on the plain image.

## Done when

The workspace has no placeholder crate and the db container is stock Postgres, or the Record says why not.

## Record

**Done.** The three placeholder crates are gone (`lapidary-build`, `lapidary-index`, `lapidary-enterprise`, 60
lines and three manifests), with `lapidary-api`'s two dependencies on them. `xtask/src/layers.rs` loses the
`Enterprise` tier, its edge arm, its message arm and the five tests that existed only for it; the binary-dependency
message checks moved into `rejects_l3_depending_on_bin` so they are still pinned. Tests that used `lapidary-index`
as a sample L2 name use `lapidary-targets`.

**The db image is stock Postgres.** `deploy/db/` held a Containerfile that installed pgvector and an init script
that created `vector` and `pg_trgm` and checked for the `turkish` text-search config. `pg_trgm` is created by
migration 0001 and ships in the image's contrib; nothing uses `vector`; Turkish search went in 0031. So `deploy/db/`
is deleted, `compose.yaml`'s `db` service uses `postgres:18` at the digest the Containerfile already pinned, and the
Containers workflow stops building `lapidary-db`. The lane test database has always been that same stock image, so
every `#[sqlx::test]` in the gate is the proof that a fresh database migrates without the package.

**Decided without the owner: two dependency moves the gate forced.** `cargo deny` failed on `main` as it stood, not
because of this goal:
- **rustls 0.23.45 → 0.23.46** — four advisories (ECH data leak, `Debug` exposing secrets, ServerHello downgrade,
  Brotli certificate bomb). A patch bump, `Cargo.lock` only.
- **zip 2.4.2 → 9.0.4** — every zip release before 9.0.3 is yanked on crates.io, and `yanked = "deny"`. The one API
  change that reached us: an entry name is now a `Result` (a name that does not decode is an error rather than a
  lossy string). `bundle.rs` refuses such an archive with a sentence, `tmf.rs` calls it malformed, and one test
  `expect`s it. No behaviour change for a readable archive; every bundle and 3MF test passes unchanged.

Gate: `cargo xtask verify slice`, 14 gates green in 239 s on a cold `target/`.
