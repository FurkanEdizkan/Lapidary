## Why

Six Phase 6 goals run in parallel against the same types, tables and routes. Those land on `main` first, so every
goal builds against something real and no two goals invent the same thing twice. Design: [`phase-6.md`](phase-6.md).

  references `part` may cascade, and `every_table_referencing_the_part_chain_is_one_purge_deletes_from`
  (`crates/lapidary-db/tests/repo.rs:2755`) fails for a new child table purge does not delete.

## Rules

## Stages

1. **Core types** — `crates/lapidary-core/src/shape.rs` (`ShapeProfile { size_mm, descriptor }`, `SHAPE_VERSION: i16 =
   1`, `DESCRIPTOR_LEN = 35`, `distance()`, `is_near_duplicate()`, `NEAR_DUPLICATE_DISTANCE = 0.04`,
   `SIZE_BAND = ln(1.02)`), `event.rs` (`AppEvent { Changed { library }, Resync }`, tagged by `type`), `link.rs`
   (`PartLinkKind { Variant, Distinct, FoldedInto }`). **Tests:** distance is symmetric and zero on itself; the size
   band admits 1.9% and refuses 2.1%; `AppEvent` serialises as the web will read it.
2. **Tables** — `0047_part_shape.sql`: `part_shape (part_id uuid PK REFERENCES part, library_id uuid NOT NULL,
   revision_id uuid NOT NULL REFERENCES revision, l0_blake3 text NOT NULL, version smallint NOT NULL, size_mm float8
   NOT NULL CHECK (size_mm > 0), descriptor real[] NOT NULL CHECK (cardinality(descriptor) = 35), computed_at
   timestamptz NOT NULL DEFAULT now())`, index `(library_id, size_mm)`; `job_outcome_known` gains `profiled`.
   `0048_part_link.sql`: `part_link (part_id, other_id → part, library_id, kind CHECK IN
   ('variant','distinct','folded_into'), created_at, PRIMARY KEY (part_id, other_id), CHECK (part_id <> other_id),
   CHECK (kind = 'folded_into' OR part_id < other_id))`, index on `other_id`. Neither cascades.
3. **Db** — `crates/lapidary-db/src/shapes.rs`: `PgShapes::record(part, revision, l0_blake3, &ShapeProfile)`, upserting
   only when the incoming revision id is ≥ the stored one (uuid v7 sorts by time, so a late backfill cannot overwrite a
   newer revision). `repo.rs`: `purge` deletes `part_shape` and `part_link` (`part_id = $1 OR other_id = $1`) before
   `part`, and the catalogue test learns both; `PgParts::rows_by_id(library, &[PartId])` on the grid's query.
   **Tests:** record, re-record newer, refuse older; purge leaves neither table holding the part.
4. **Wire types** — `crates/lapidary-api/src/likeness.rs` (`Likeness { profiled, identical, near_duplicates, similar,
   variants }` of `PartCard`, `DuplicateClusters { clusters: [{ parts, identical }], unprofiled }`, `SetLink { kind }`,
   `FoldPart { into }`, and the signature G4 will call: `pub(crate) async fn clusters(db, library, since)`), and
   `dashboard.rs` (`Widget` — the seven kinds — `ResolveRequest`, `ResolveResponse`, `KeyResult`); each with
   `pub(crate) fn routes() -> Router<AppState> { Router::new() }` merged for the api role. `to_card` becomes
   `pub(crate)`.
5. **Web and docs** — `web/src/lib/strings.ts`: `titles.dashboard`, `titles.duplicates`, and empty top-level blocks
   `dashboard: {}` and `likeness: {}` in separate places; `cargo xtask export-bindings`. (The ROADMAP already records
   the no-pgvector decision, from B0.)

## Record

What landed, and where it differs from the stages above (lanes: build against this, not the stage text).

- **Core** (`lapidary-core`): `shape.rs` as specified, except the size band is `shape::size_band()` — a function,
  because `f64::ln` is not `const`. `AppEvent` serialises as `{"type":"changed","library":…}` / `{"type":"resync"}`;
  `PartLinkKind` is `"variant" | "distinct" | "foldedInto"` on the wire and `variant|distinct|folded_into` in the
  table (`as_str`/`parse`).
- **Tables:** `0047_part_shape.sql` (and `job_outcome_known` gains `profiled`), `0048_part_link.sql`, as specified.
- **Db:** `PgShapes::record(part, revision, l0: BlobHash, &ShapeProfile) -> bool` stamps `SHAPE_VERSION` itself and
  writes nothing for an older revision or a missing part; `PgShapes::of_part(part) -> Option<ShapeRow>` (added, for
  G2's staleness check and G3's tests) returns the row stale or not. `PgParts::purge` deletes `part_shape` and
  `part_link` (either side) before `revision`; the catalogue test knows both. `PgParts::rows_by_id(library, &ids,
  shows: Shows)` — **takes `Shows`** (added): likeness wants live parts, the folds list wants removed ones. Rows come
  back in the order asked; ids outside the library or on the other side of `shows` are left out.
- **Api:** `likeness.rs` — `Likeness`, `DuplicateCluster`, `DuplicateClusters`, `SetLink`, `FoldPart`, plus `Fold {
  part, into: PartCard }` (added: what `GET /api/libraries/{id}/folds` answers, so G3 and G6 agree on it), and
  `clusters(db, library, since: Option<jiff::Timestamp>) -> Result<DuplicateClusters, DbError>`, which finds nothing
  until G3. `dashboard.rs` — `Widget` (tagged by `kind`), `FacetKind`, `WidgetRequest`, `ResolveRequest`,
  `ResolveResponse`, `KeyResult`, `WidgetResult` (tagged by `status`: `ok { value } | timedOut | failed { message }`),
  and `WidgetValue` (added: tagged `kind` + `value`, one per widget kind — `LibraryStorage`, `InstanceStorageView`,
  `PartCard[]`, `FilteredParts { name, parts }`, `FacetValue[]`, `QueueSummary { pending, running, failed }`,
  `DuplicateSummary { clusters, unprofiled }`), so G5 draws against real types while G4 builds. `limit: u8` does not carry the design's caps (≤ 12 for `recent` and `savedFilter`):
  **G4 enforces them** and G5 offers nothing past them. Both modules carry
  `#[allow(dead_code)]` on their `mod` line in `lib.rs`; **G3 and G4 remove it** when they route. Their `routes()` are
  merged at the end of the api role's chain. `parts::to_card` is `pub(crate)`.
- **Web:** `titles.dashboard`, `titles.duplicates`; empty `dashboard: {}` (above `crash`) and `likeness: {}` (above
  `removal`) in `strings.ts`; 19 new bindings.
- **Also:** `.gitignore`'s `node_modules/` became `node_modules`, because a lane's `web/node_modules` is a symlink and
  the trailing slash matches directories only.
- **Purge and folds:** `purge` deletes `part_link` rows from either side, so purging a *kept* part leaves anything
  folded into it removed with no `foldedInto` row — an ordinary removed part. Expected; G3 and G6 treat it so (see
  `phase-6.md`).
- **Tests:** core 105 (4 new); `tests/shapes.rs` 5 (record and read back; newer replaces, older refused, same revision
  replaces; a missing part records nothing; purge takes profile and links from either side; `rows_by_id` order and
  sides). Mutation: dropping the `revision_id <=` guard fails the newer/older test.
