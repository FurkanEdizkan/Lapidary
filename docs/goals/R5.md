# R5 — Trim `lapidary-cad` to parsers and measurement

**Status:** ready at f2e2356, gate log target/verify-R5.log — every commit after it changes only
`docs/goals/R5.md` and `README.md`, and no gate step reads either (`export-agents-md` renders
`AGENTS.md` from `CLAUDE.md` alone; `check-strings` scans `.rs`).
**Branch:** `refactor/mesh-facts-only`
**Wave:** 5 · **Kind:** Rust · **Depends on:** R2, R3 (the modules are only dead once both callers are gone) · **Migrations:** —

## Why

`lapidary-cad` was a CAD kernel crate. What the product still needs from it is small and worth keeping: parse
a mesh file, say how big it is. The owner kept the cheap facts deliberately — for a miniatures library the
size in millimetres is the fact that decides whether something is 28 mm scale and how much resin it costs.

Everything else in the crate existed to feed renders or the kernel.

## Facts checked (2026-10-03, `73c4836`)

- Survives: `stl.rs` (516), `obj.rs` (280), `tmf.rs` (1,119), `measure.rs` (301) — parsers and measurement.
- Goes: `cluster.rs` (560, the LOD ladder), `glb.rs` (506), `raster.rs` (430, the CPU rasteriser and its
  golden-bytes test), `mock.rs` (126), `tests/calibration.rs` (454), and the assembly/entity types in
  `kernel.rs`. About **3,400 of 5,300 lines**. *(The "~121 inline tests" this file first quoted is now too
  high: R3 took `MeshKernel`'s rung and thumbnail cases with the `produce` list, so count before you promise a
  number. R3 also left `cluster()`, `render_thumbnail()`, `GLB_VERSION` and `RASTER_VERSION` with no caller
  but the version string, and `CadError::Unrenderable` unreachable beside the six R2 left.)*
- **The `Kernel` trait had one shipped implementation and one double.** `lib.rs`'s own doc already admits
  `MockKernel` "is unreachable from the ingest path today — `handler.rs` names `MeshKernel` directly". An
  interface with one implementation, for one caller, is the thing to delete.
- **One caveat:** `mock-kernel` currently gates `worker_router`/`spawn_worker` in
  `bin/lapidary-server/src/main.rs:289`. That gate needs an honest replacement — an explicit `worker`
  feature, or nothing — rather than a silent deletion.

## Rules

- `handler.rs` calls free functions: `parse(bytes, format)?` then `measure(&mesh)`. No trait, no params
  struct, no `produce` list.
- `check-layers` stays green: `lapidary-api` must never link `lapidary-cad`.
- Keep the exports (`export_stl`, `export_3mf`). They are the slicer handover, they are pure Rust, and
  downloads are not what this pivot is removing.

## Stages

1. **Delete the render modules** and the trait, and move the ingest path onto free functions.
   **Tests:** `cargo test -p lapidary-cad` is parsers and measurement only, and still covers every format the
   library takes.
2. **Replace the `mock-kernel` gate** on the worker router with something that says what it means.
   **Tests:** the worker role still starts, and the api role still refuses to.

## Recorded, not built

otherwise it goes with the rest, and the Record says it went.

### The trait: deleted, and the race tests kept

**The judgement.** `Kernel` had one shipped implementation and one double, `handler.rs` named the
implementation directly, and `lib.rs`'s own doc already said the double was unreachable from ingest.
Against that, R2 recorded a real reason to keep the field: `MeshKernel` is synchronous all the way
down, so it was *the only instant at which one of two jobs racing over one new path can be
suspended*, and two slice-1 §3.3 races are staged through it.

Both halves of that are true, and they are about different things. The races need **an await point
inside `index`, between the read that finds no part at the path and the insert that takes it** — they
do not need a kernel, a version, a `produce` list or dynamic dispatch. So the await point stays and
everything around it goes:

```rust
pub pause: Option<Pause>,          // on WorkerHandler, None in production
pub struct Pause { pub reached: Arc<Notify>, pub release: Arc<Notify> }
```

awaited immediately before `parse`, which is exactly where `HeldMesh::process` suspended. Both races
keep every assertion they had; the 24-line double became a 4-line struct literal. What that bought,
beyond the 478 lines of `kernel.rs` + `mesh_kernel.rs`: `KernelParams` (with the `produce` list that
R3 had already emptied at every call site), `KernelOutput` with `exports`/`unproduced`,
`KernelVersion`, `Unproduced`, `async_trait` on the hot path, `kernel_for`'s `&dyn Kernel`, and
`derive.rs`'s `missing()` — a `HandlerError` for "the kernel was asked for one thing and returned
nothing", a branch no shipped kernel could reach, which one exhaustive `match want` now makes a
compile error instead.

**`held()` bounds the wait, and that is not tidiness.** Both races `await` on `reached`; a seam that
stops firing made this file **hang** rather than fail — under the machine-wide compile lock, with no
message. `held()` wraps it in a 10-second `tokio::time::timeout` with a sentence that names the
field. `mutate-r5.sh`'s `pause-never-fires` is what proves the bound works: it reports
`the held job must reach the parse: WorkerHandler::pause never fired: Elapsed(())` in 10 seconds
instead of sitting there.

### The version string stays exactly as it was, and that is the decision

`kernel_version(format)` returns **`mesh {format}-1+glb-3+cpu-1`**, unchanged, although `glb-3` named
the glTF writer and `cpu-1` the rasteriser that this goal deleted. R3 left it alone as a trap it had
spotted; R5 leaves it alone because it is the right answer rather than a deferral:

- the column exists to say **"the bytes this build would write could differ"**. Nothing R5 removed can
  change an export's bytes — `write_stl` and `write_3mf` are untouched, byte for byte — so by the
  column's own contract the string **must not** move;
- `PgJobs::enqueue_stale_derivatives` compares it against every stored export row, so a bump would
  queue a rebuild of every export in the corpus at the next worker start, each one producing a
  byte-identical file.

It is now one function with the reason in its doc, instead of two constants in deleted modules. Its
test is written as **three literals**, not against the function's own constants, because a cache key's
guard has to fail when the key changes: `mutate-r5.sh`'s `version-bumped` and `version-bumped-as-stored`
show that `lapidary-cad` and the stored-column tests in `tests/handler.rs` each notice independently.

### The `mock-kernel` gate, replaced rather than deleted

`bin/lapidary-server`'s feature is **`worker`**. It gates the same three optional dependencies it
always did — `lapidary-cad`, `lapidary-ingest`, `lapidary-jobs` — so nothing about which image links
what changed, and `check-deploy` reads the same shape. That manifest's own comment had called the old
name "a slight misnomer" and kept it because renaming meant touching `deploy/compose.yaml`,
`deploy/Containerfile` and `xtask/src/deploy.rs`'s fixtures "for no behavioural gain". With the double
deleted the name described nothing at all, and an operator reading `SERVER_FEATURES: mock-kernel` on
the one service that runs real ingest has every reason to think the worker is a stub. Renamed in
`compose.yaml`, the Containerfile's comments, `.github/workflows/containers.yml`, `README.md`,
`deploy.rs`'s rule and its fixtures, both `#![cfg]`-gated peer tests, and `main.rs`.

**Both halves of stage 2 were run, because the gate cannot see one of them.** `verify slice` compiles
with `--all-features`, so the `not(feature = "worker")` arms — the refusal that is stage 2's second
half — are never built, linted or exercised by it. Checked by hand, two debug binaries against a
scratch database on the lane's Postgres:

- **`--features worker`, `LAPIDARY_ROLE=worker`:** starts, `/api/healthz` answers 200, and it logs
  `role=worker`, `parsers=mesh, for stl, obj and 3mf`, `job worker starting … concurrency=4`,
  `quarantine sweep starting quarantine_days=30`.
- **default features, `LAPIDARY_ROLE=worker`:** logs
  `parsers=none — this build has no parsers and no ingest (build with --features worker)` and then
  exits 1 with *"Could not start as worker: this binary was built without ingest support. Rebuild with
  `--features worker` — deploy/compose.yaml does this automatically for the worker service."*
- `cargo test -p lapidary-server` with default features: 26 tests, green.

The startup line is **`parsers=`, not `kernel=`**, and `kernel_description` is `parsers_description`.
A log field named for a kernel in a product with no kernel is the same stale name this wave keeps
finding; nothing in `scripts/` greps it.

### A refusal R2 built, kept explicit and given its first test

`kernel_for` did two jobs — refuse a B-rep format, and hand back a kernel — so splitting it turned the
first into a free `refuse_b_rep(format)` with **two** call sites rather than one structural guarantee.
The second looked like belt-and-braces, and the question whether to keep it had to be answered rather
than assumed. **It is reachable, and nothing tested it.**

**An install upgraded across the pivot still holds the revisions a STEP file ingested before it.** R2
kept `revision.face_count` and `edge_count` for exactly those rows. `derive_one` takes its format from
`file.format` on the revision the payload names, and `derive.rs`'s `build()` — behind
`POST /api/parts/{id}/exports/{format}` — reads `latest_revision(part)` and enqueues without looking
at its format at all (checked; the route's only guard is that `{format}` is `stl` or `3mf`). So one
click on a part that has been in the library for a year arrives in `derive_one` with `format = "step"`.

R2's `kernel_for` already refused it there, so this is not a hole R5 closed — it is a behaviour R5
could easily have refactored away as redundant, and now cannot: without it the person reads the
parser's "this build has no parser for the step format" instead of the sentence every other path gives
them. `an_export_of_a_pre_pivot_step_revision_is_refused_in_the_same_words` seeds that row (ingest an
STL, then restate `file.format`) and asserts the message is `lapidary_core::cad_refusal("step")`
exactly, `Permanent`, and that nothing is written. It is the first test over that path.

### What else moved

- **`CadError` is four variants**, all of them a verdict on immutable bytes: `MalformedMesh`,
  `ArchiveRefused`, `ExportFailed`, `UnsupportedFormat`. Nine went — R2's six (`UnsupportedSchema`,
  `Timeout`, `KernelCrashed`, `KernelUnavailable`, `KernelOutputUnreadable`, `CadRefused`), R3's
  `Unrenderable`, and `NoFixture` with the double. So **`classify_cad` has no `Transient` arm left**.
  It stays as a function rather than collapsing into `HandlerError::Permanent` at three call sites, for
  `classify_db`'s reason: the next `CadError` worth retrying gets one arm here instead of a decision at
  each caller. `a_kernel_crash_is_retried_not_recorded_as_a_refusal` became
  `every_parser_verdict_is_permanent_rather_than_retried`, over all four variants rather than a
  representative one.
- **`measure` is one function, not two.** `pub fn measure(&Mesh) -> MeshMeasurements` had no caller
  outside its own tests; the pipeline used the `pub(crate) measured`, which returns the centre of mass
  as well. The thin wrapper is gone and `measure` returns the pair, which is what this goal's rule
  asks for and what both callers want.
- **`enqueue_stale_derivatives` walks the three mesh formats**, not six. It chained `CAD_FORMATS` and
  dropped them inside the loop via `kernel_for`'s `Err`, which read as if B-rep formats were swept and
  found nothing; no export row can name one.
- **`parse` lowercases the format and is tested for it.** It always did; nothing asserted it, and
  `source_format` is the only caller that guarantees it.
- **The crate's public API is eight items**: `CadError`, `Mesh`, `parse`, `measure`, `kernel_version`,
  `IMPLEMENTATION`, `write_stl`, `write_3mf`. It was **23**, or 24 with `MockKernel` under the feature.
  `parse_stl`, `parse_obj` and `parse_3mf` are reached through `parse` and nowhere else; exported one
  by one they were three more ways for a caller to pick the wrong parser for an extension it had not
  lowercased.
- **Unused dev-dependencies removed from `lapidary-ingest`** while its manifest was open: `image`
  (its comment described a `tests/scan.rs` that decoded a stored thumbnail — R3 took that) and
  `async-trait` (`HeldMesh` was its only user).

### Decided without the owner

1. **The `Kernel` trait is deleted and the race tests kept**, with `WorkerHandler.pause` as the
   await point. Reasoning above. The alternative R2 left open — keep the trait to stage the races —
   costs 478 lines of types, a feature name and an unreachable error branch to obtain two `Notify`
   handles.
2. **`kernel_version` is frozen at `mesh {format}-1+glb-3+cpu-1`**, dead tokens and all, and the
   reason is written into its doc so the next person to tidy it reads why first. It changes when the
   parsers or the export writers change. **R4 should know this is still true**: R4.md's stage 1 weighs
   deleting export rows against the version not having moved, and it has not moved.
3. **`refuse_b_rep` stays in `derive_one`** rather than being left to the parser's own refusal, because
   the path is reachable on an upgraded install (above). It is R2's sentence, not a second one.
4. **`main.rs`'s startup field is renamed** `kernel` → `parsers`. Nothing in `scripts/` or the gate
   reads it. One line of history quotes the old form — `docs/ROADMAP.md:3899`, R2's measurement of a
   kernel-less worker starting — and it is the lead's file; it was true when it was written.
5. **A parse-rate harness was not built.** This goal's "Recorded, not built" left it as the owner's
   call, and R3 recorded that `tests/calibration.rs` was the only thing that ever measured how many of
   the 1,095 real files we can read. **Recommendation: build it, but not as a test.** It is now about twenty lines — walk the
   corpus index, `lapidary_cad::parse`, count by error variant — and that is the shape it should have:
   a `cargo xtask` subcommand or a small binary an operator can point at a folder, not a `#[test]`
   that reads a 320 GB mount the gate must not touch. The number it produces is a product fact worth
   having (which of a stranger's files this library can read), and it belongs to nobody's goal yet.
6. **One pre-existing warning is left alone.** `Config.example_dir` is `never read` in a
   default-features build, because only `seed_examples` reads it and only the feature compiles that.
   It predates this goal and the gate cannot see it (`--all-features`). A `#[cfg]` on the field would
   mean a `LAPIDARY_EXAMPLE_DIR` that figment silently ignores on the api image, which is the shape
   `main.rs` already warns about for the four worker knobs.
