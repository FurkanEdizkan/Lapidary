# R5 — Trim `lapidary-cad` to parsers and measurement

**Status:** open
**Branch:** `refactor/mesh-facts-only`
**Wave:** 5 · **Kind:** Rust · **Depends on:** R2, R3 (the modules are only dead once both callers are gone) · **Migrations:** —

## Why

`lapidary-cad` was a CAD kernel crate. What the product still needs from it is small and worth keeping: parse
a mesh file, say how big it is. The owner kept the cheap facts deliberately — for a miniatures library the
size in millimetres is the fact that decides whether something is 28 mm scale and how much resin it costs.

Everything else in the crate existed to feed renders or the kernel.

## Facts checked (2026-10-03, `73c4836`)

- Survives: `stl.rs` (516), `obj.rs` (280), `tmf.rs` (1,119), `measure.rs` (301) — parsers and measurement.
- Goes: `cluster.rs` (560, the LOD ladder), `glb.rs` (506), `raster.rs` (430, the CPU rasteriser and its
  golden-bytes test), `mock.rs` (126), `tests/calibration.rs` (454), and the assembly/entity types in
  `kernel.rs`. About **3,400 of 5,300 lines**. *(The "~121 inline tests" this file first quoted is now too
  high: R3 took `MeshKernel`'s rung and thumbnail cases with the `produce` list, so count before you promise a
  number. R3 also left `cluster()`, `render_thumbnail()`, `GLB_VERSION` and `RASTER_VERSION` with no caller
  but the version string, and `CadError::Unrenderable` unreachable beside the six R2 left.)*
- **The `Kernel` trait had one shipped implementation and one double.** `lib.rs`'s own doc already admits
  `MockKernel` "is unreachable from the ingest path today — `handler.rs` names `MeshKernel` directly". An
  interface with one implementation, for one caller, is the thing to delete.
- **One caveat:** `mock-kernel` currently gates `worker_router`/`spawn_worker` in
  `bin/lapidary-server/src/main.rs:289`. That gate needs an honest replacement — an explicit `worker`
  feature, or nothing — rather than a silent deletion.

## Rules

- `handler.rs` calls free functions: `parse(bytes, format)?` then `measure(&mesh)`. No trait, no params
  struct, no `produce` list.
- `check-layers` stays green: `lapidary-api` must never link `lapidary-cad`.
- Keep the exports (`export_stl`, `export_3mf`). They are the slicer handover, they are pure Rust, and
  downloads are not what this pivot is removing.

## Stages

1. **Delete the render modules** and the trait, and move the ingest path onto free functions.
   **Tests:** `cargo test -p lapidary-cad` is parsers and measurement only, and still covers every format the
   library takes.
2. **Replace the `mock-kernel` gate** on the worker router with something that says what it means.
   **Tests:** the worker role still starts, and the api role still refuses to.

## Recorded, not built

`tests/calibration.rs` is the only thing that ever measured **how many real files we can read** across the
1,095-file corpus. Keep that harness if the owner wants the parse-rate number, stripped of profiling —
otherwise it goes with the rest, and the Record says it went.

## Done when

`verify slice` green, `check-layers` green, and the crate is parsers plus measurement with nothing in it that
renders.
