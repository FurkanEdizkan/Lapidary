# P4 — The explore landing

**Status:** open
**Branch:** `feat/explore-landing`
**Wave:** 5 · **Kind:** web · **Depends on:** G3, G4, G5, P2, P3 · **Migrations:** —

## Why

An archive opens on a page that invites a walk around: what arrived lately, what the big categories are, who the
creators are, which tags exist, a few things picked at random. Lapidary opens on a grid of everything, which is the right
page for somebody who knows what they want and the wrong one for somebody who does not. Phase 6 builds every piece this
needs — the widget renderers (G5), one batched resolve (G4), the duplicates line (G3) — and P2 and P3 add creators and
tags, so this goal is an arrangement, not an engine.

## Facts to check before building

- `crates/lapidary-api/src/dashboard.rs` as G4 left it: the widget kinds, `WidgetValue`, and whether `POST
  /api/dashboard/resolve` will answer everything this page needs in **one** call (it takes 1–32 keys).
- G5's widget registry and renderers — this page reuses them; if a renderer is only reachable from the dashboard's
  layout, say so in the Record rather than copying it.
- `docs/FEATURES.md` §8: **per-widget polling is a stated non-goal** ("self-inflicted DoS"), and a web test fails if
  `refetchInterval` appears under the dashboard's directory. The same rule holds here.
- Whether "random picks" can be stable for the length of a visit without a per-view query (a seed in the URL, or the
  keyset the grid already has).

## Rules

- **One request.** The page resolves its panels in a single `POST /api/dashboard/resolve`, and a test asserts exactly one
  network call on load.
- No new API. If a panel wants something resolve cannot answer, the panel is cut or the widget kind is G4's to add —
  this goal does not grow the Rust side.
- It is a landing page, not a dashboard: nothing here is draggable, resizable or saved. The dashboard is where a person
  arranges things.

## Stages

1. **The page** — `/explore`: latest additions, the biggest categories, creators, the tag cloud, a few random picks, and
   the "N look like parts already here" line, each panel a widget renderer, all from one resolve.
   **Tests:** one `fetch` on load; a panel whose key came back `timedOut` says so and the rest still draw; an empty
   library reads as an invitation to add something, not as an error.
2. **The way in** — `/explore` in the nav beside the grid, and the first-run path leads here rather than to an empty
   grid.
   **Tests:** the nav's current item is marked; the route has a title; reduced motion draws it with no staggered entry.

## Done when

`/explore` answers in one request with every panel drawn, nothing polls, `verify slice` is green, and the Record names
the measured settle time.
