## Why

The rig asserts a product that no longer exists, and the documents describe one. Of the two, **the documents
matter more**: `CLAUDE.md` is the constitution every future session reads first, and three of its
non-negotiable rules are now false.

## The rig

**Dead:** `thumbnails` (asserts every card carries a `data:` render), `duplicates`, `section-explode-pmi`
(the only flow that proved the real kernel ran), `reduced-motion-no-spin`, `hover-heap` (50 hovers for WebGL
contexts that no longer exist), and `exit2` with `scripts/e2e/exit2.py`.

**Replaced:**

  one-request property is the half of the old flow worth keeping.

- `part-detail` repoints from a STEP fixture to a mesh; `measure` loses its "L2 has to arrive" settle and

   then `--min-free 2`, with the reason written into both. **The next container goal needs the owner to
   reclaim space first**, and `docker builder prune` is the obvious candidate now that there is no OCCT
   layer left to lose.

   `PRODUCT.md`'s copy of the same example was corrected here to `lapidary_core::cad_refusal`'s own

3. **`DESIGN.md` needs a goal of its own.** It is 600 lines of visual system, six of whose named places

different presses: **open** (card press → the part on screen, no mesh involved) and **draw** (**view**

**One correction to R2, and it matters to anyone quoting these numbers.** R2 recorded that Docker's size

### Bugs in the rig, found only by running it

Six, and three of them made something report success:

1. **The seed wrote no `seed.json` and exited 0.** A `seed_check` detail written across two source lines
   carries a real newline, the TSV is `name<TAB>ok<TAB>detail`, and the python that reads it splits on
   tabs — so the second half of such a detail is a line with no tabs, the writer raised, its traceback
   went to stdout, and **the heredoc's failure was never checked**. The seed printed "seed facts and 15
   checks in …" about a file that did not exist, and `drive` then refused to start. Details are flattened
   now and the writer is checked: a seed that cannot write that file dies saying so.
2. **`max(uuid)` does not exist in Postgres.** The restart check's watermark came back empty, every query
   off it failed on `uuid > ''`, and the check reported **`? job(s)`** — a check that had silently
   stopped measuring. It is `max(id::text)` now, which is exact rather than a fudge: a uuidv7 puts its
   timestamp in the leading hex digits, so lexicographic order on the canonical form is time order. The
   `${jobs_after:-99}` default is deliberate for the same reason — an empty answer must read as a failure
   and not as zero.
3. **The first draft of that check counted by clock and read 1,649.** `created_at > now() - interval '5
   minutes'` caught the whole scan, which had finished two minutes earlier. The watermark is exact.
4. **`derivative` is `UNIQUE (revision_id, kind)`**, so the second run of the seed died on a duplicate
   key — because the first run's restart had queued the rebuild and **the worker wrote it**. That is the
   check working. The plant now picks a revision with no export, and the cleanup takes the real export
   away too, which leaves the library with no derivatives at all, as a freshly seeded one has.
5. **The Governed uploads were adding a revision per seed.** The vee-block's path holds the *stamped*
   bytes after the deliberate re-upload, so on a second seed the pristine file at that same path is new
   bytes at an old path — in a controlled library, a revision. The "not adding another" guard only ever
   guarded its own re-upload. Measured: three revisions on a stack seeded three times, where the fixture
   is "two". The four uploads are skipped when the path is already held.
6. **A backtick inside a `//` comment inside a template literal ends the literal.** T1 wrote this down
   and it caught me anyway, in the new `pictures` flow; `node --check` found it.

And one in `open-timing.mjs`, which is the same class as the three above: **`open()` returned on the
quick look's frame rather than on its content**, so `draw()` looked for the **view** button before the
detail query had answered. Round 0 reported six "this part offers no 3D view" and round 1 six draws,
purely because react-query had the answer cached the second time — and the summary line said "6 of 12
parts offer a view", which reads as a fact about the library. It waits for the panel to name the part
now, which is also the right definition of "part open", and the swallowed error says itself out loud.
**12 of 12 after the fix.**

### Mutation check

`target/mutate-r6.sh` (`static|web|seed|all`), logs in `target/mutations-r6/`. These are not cargo
tests, so there are three layers: `check.sh` (no container, four seconds), the rig driven against the
live stack with a mutated bundle `docker cp`'d into the web container (`npm run build` takes no compile
lock and no image is rebuilt — about 30 s a case, group.sh's own `dist` trick), and the seed's own
assertions. **Nine cases, nine caught**, every failure message read and matched to the rule it claims.

| group | mutation | caught by, and what it said |
|---|---|---|
| static | `unlisted-function` | `stack.sh defines 38 functions and this check names 37` — the new whole-list check, which is why it exists |
| static | `renamed-view-string` | `a string a flow depends on has been renamed` |
| web | `card-fetches-per-card` | `pictures`: `50 of 77 requests address a part or a blob` — at both widths |
| web | `card-shows-nothing` | `pictures`: `49 of 50 cards show neither a picture nor their format` |
| web | `viewer-reads-an-export` | `view-original`: `pressing "View in 3D" never reported a first frame` |
| web | `viewer-also-fetches-an-export` | `view-original`: `the view fetched something we produced rather than the original` — the clause the one above could not reach |
| seed | `one-step-fixture-missing` | `the six B-rep fixtures are refused … — 5 of 6 refused by name` |
| seed | `restart-without-its-control` | `a restarted worker queues the one stale export and nothing else — 0 job(s) queued by the restart, of kind(s) none` |
| seed | `a-thumbnail-row-by-hand` | `derivative holds no render kinds — 1 rows of a kind nothing builds; kinds present: thumbnail` |

**The fourth web case exists because the third did not test what it looked like it tested.** Pointing
the viewer at `?variant=3mf` is caught — but by the *frame* assertion, because that URL 404s on a part
with no export written, so the view never drew and the flow stopped before the network clause. Caught is
caught, and the "nothing GLB-shaped" clause was still unproven. `viewer-also-fetches-an-export` leaves
the paint alone and adds a stray fetch of something we produced, so `?variant=original` is there, a
frame arrives, and **only** the second clause can fail.

**Two were written down rather than counted**, which is R3's rule about a mutation that cannot express
the violation:

- **"The view fetches nothing GLB-shaped" is held by absence as well as by the flow.** There is no GLB
  writer, no rung route, no `?variant=l0`; a mutation that made the application fetch one would have to
  rebuild the pipeline the pivot deleted. The clause is reachable, and the fourth web case above proves
  it fires — but nothing in this build can produce the real violation.
- **"The refusal names the format of the file it refused" is R2's rule, held by R2's test.**
  `the_refusal_names_the_format_and_what_this_library_takes` and two of R2's thirteen mutations cover
  it. The seed's check adds **end-to-end reach** over the real binary and six real files, not a new
  rule, and `one-step-fixture-missing` is what proves the check reaches them and counts them. Breaking
  `cad_refusal` to re-prove R2's point would have cost a worker rebuild on a root disk with 2 GB left.

The two fixture perturbations are labelled as such rather than called code mutations:
`one-step-fixture-missing` moves a file out of the ingest tree, and `a-thumbnail-row-by-hand` inserts a
`thumbnail` row in raw SQL — the only way to produce one, since `DerivativeKind` cannot name it, which is
R3's whole point. What each proves is reach, not behaviour.

**The harness learned two things about itself, both while being used:**

- **It takes a lock now.** Two `web` runs were started by hand and interleaved, each mutating and
  restoring the same files — so one run's restore can put the *other* run's mutation back as the
  original, and the sha256 check would then pass against the wrong bytes. It was caught by reading
  `git status` rather than by the script, which is the wrong way round. `flock -n` on a file in the log
  directory, and the second run says whose lock it is.
- **`drive --only` no longer runs the timing half.** `flows.mjs` already skips its extra sessions under
  `--only`; `cmd_drive` ran `open-timing.mjs` regardless, which under `viewer-reads-an-export` meant
  **twelve 60-second waits after the flow had already failed in one second** — 12 minutes of a mutation
  campaign, in exactly the case somebody reaches for `--only`. `--only` means run one flow.

Recovering from the interleaved run needed `git checkout -- web/src/lib/api.ts`, which is the command
R1's Record warns about. It was safe here and it was checked before it was run: the only uncommitted
work under `web/` was `web/scripts/open-timing.mjs`, and `api.ts` had matched `HEAD` before the mutation
touched it. Said out loud because the next person should check the same thing rather than inherit the
habit.
